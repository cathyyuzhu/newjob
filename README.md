# 职达 Landed — 求职路上，滤掉噪音，只留信号

本地运行的小型 Web 程序（代码目录仍叫 `newjob`）：

0. **先上传你的简历**（`.docx`）。整个应用只认这一份，下面第 2、3 步全靠它；还能对它跑一次 AI 体检，按逐段改写建议一键生成优化版。
1. 按你设置的关键字每天定时自动搜索 Indeed 和 LinkedIn 上的新职位，去重后存入"待审核"列表。
2. 待审核列表里的新职位会**自动**调用 LLM（默认 Claude API，也可切换成更便宜的 DeepSeek API）拿你的简历完整走一遍 `jd-resume-matcher` 技能的双因子匹配度分析，写入 `JD匹配追踪表.xlsx`。定制简历（docx）和 cover letter **不会**跟着自动生成——看中了再去职位详情页点按钮单独生成，或者对一批职位批量生成，见「定制简历 / Cover Letter 怎么生成」。也可以对单条职位点"AI 分析"手动重新触发（比如之前分析失败想立刻重试）。
3. 每条职位有自己的详情页：完整匹配分析结论、可以自定义**标签**分类、能跟 AI **对话**追问这条职位、能记**备注**（AI 回答一键存、也能手写）。
4. 投递之后把状态改成「面试中」，会**自动**生成一份针对这家公司/这个岗位的面试准备材料（公司背景、预测面试题+答法、缺口应对话术、反问清单，连同职位详情页记的备注一起展示）。另有一个跨职位复用的通用面试题库（自我介绍 / STAR 故事 / 逐段过往工作 / 通用问题，中英双语）。

这七块用到 AI 的地方可以各自挑模型（Claude / DeepSeek），见下面「选用哪个模型」。

## 重要说明 / 边界

- **Indeed**：通过 [python-jobspy](https://github.com/speedyapply/JobSpy) 调用其公开搜索接口抓取。
- **LinkedIn**：LinkedIn 没有公开的职位搜索 API，这里用 python-jobspy 做**非官方抓取**（绕过登录墙）。这可能违反 LinkedIn 的服务条款，存在账号/IP 被限流或封禁的风险。这是你在需求确认时明确选择接受的方案，如果之后想改成"仅手动粘贴 LinkedIn JD"（更保守、零风险），把设置页里 `sites` 的 `linkedin` 去掉即可（或直接编辑 `config.json`）。
- **自动分析会产生 API 调用费用，且是自动触发的**：每次搜索（定时或手动点"立即搜索一次"）**这次新增**的职位会自动分析，不需要你逐条点击；这意味着调用次数/费用直接取决于每次搜索新增多少条职位（关键词×城市组合越多、`results_wanted` 越大，新增越多）。这一步只算匹配度、**不生成定制简历/cover letter**（那一步改成按需触发，见后面「定制简历 / Cover Letter 怎么生成」），所以比以前更省。按 DeepSeek 的价格通常每天几毛到几块钱，按 Claude Sonnet 则贵一个数量级左右，具体看每天新增职位数量。为了少花冤枉钱，两种明显不相关的噪音结果会被自动跳过、不调用 LLM：职位标题跟搜索关键词完全不沾边的（比如搜"AI产品经理"混进来的"Clinical Research Lead"），以及职位地点跟设置里的城市列表完全对不上的（比如用"Remote"搜出来的某个不相关国家坐班职位）——这两个粗筛只影响批量自动分析，手动点单条"AI 分析"总会调用。改了城市设置后，之前用旧设置搜到的、现在已经不符合新设置的"待审核"记录不会被自动删除或忽略，只是以后不会再被自动分析，想清理需要自己手动标记忽略。如果想改回"只分析我手动选的职位"，把 `scheduler.py` 里 `_run_job()`、`app.py` 里 `/api/search/run` 和启动时调用 `analyze_pending_jobs()` 的地方去掉即可，不用改其余代码。
- **批量生成定制简历/Cover Letter 也会产生费用**：列表页顶部"批量生成材料"按钮对**当前筛选出来的职位**生效，点之前会弹一次确认框告诉你条数；已经生成过的职位会被自动跳过，不会重复烧钱，但没生成过的每条都是一次独立的 LLM 调用，筛选范围大的时候先看一眼条数再点。
- **把正在分析的职位标记「忽略」，这条职位的分析会被中断**：那次 LLM 调用没法从外部真的打断（网络请求已经发出去了），但结果不会写进库和追踪表，跟没跑过一样；批量分析队列里的其它职位不受影响，会继续正常跑完，不是整批停下来（那是顶部"停止分析"按钮的行为）。
- 待审核职位不会因为分析完成就消失或改变筛选状态——它还是"新"，直到你手动标记"已收藏"/"忽略"；分析结果只是让职位卡片多了个匹配度百分比。
- **没上传简历时，匹配分析、面试准备、题库起草都会停用**，点了会弹一条带「去上传」按钮的提示，而不是跑出一堆失败记录。搜索不受影响（照常抓职位入库），只是抓完不会自动分析。
- 页面顶部的四张统计卡片都可以直接点击当筛选用：待审核 / 已收藏 / 已忽略按审核状态筛，「重点关注」是独立开关（可以跟前三者叠加）。再点一次已选中的卡片取消筛选。
- 只能本地运行（你自己电脑开着的时候才会定时执行）。关机/程序退出后不会补跑错过的当天任务；但程序下次启动时会自动补跑一批之前遗留的、还没分析成功的"新"职位——为了避免历史积压太多导致启动后一次跑很久很久，这个补跑限制了最多条数（`app.py` 里的 `STARTUP_BACKLOG_LIMIT`，默认 5），不会一次性清空所有积压，想加快清理可以改大这个数字或者多重启几次程序。日常新搜到的职位不受这个上限影响。
- **LinkedIn Easy Apply 半自动投递会操作你真实登录的 LinkedIn 账号**，风险比上面"非官方抓取"更高一层——抓取是匿名只读请求，这个功能是在一个真实登录会话里做交互操作。缓解方式是：真实可见浏览器窗口（不是后台隐形操作）+ 会自动填写/回答已经在设置页配置过的字段和问题、自动点"下一步"翻页，但遇到没配置过的问题、或者已经翻到最后确认页时一定会停下来；代码里没有、也不会有点击最终"提交申请"的逻辑，这一步永远需要你本人在弹出的窗口里亲自确认，详见下方"LinkedIn Easy Apply 半自动投递怎么用"。

## 安装

```bash
cd newjob
python3 -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## 配置 API Key（自动分析功能必需）

自动分析功能需要调用 LLM API，二选一，通过环境变量传入，不写进 `config.json`：

**Claude（默认）** — 在 https://console.anthropic.com 申请 key：

```bash
export ANTHROPIC_API_KEY=sk-ant-xxxxx   # Windows: set ANTHROPIC_API_KEY=sk-ant-xxxxx
```

**DeepSeek（更便宜，价格约为 Claude 的十分之一到二十分之一）** — 在 https://platform.deepseek.com 申请 key：

```bash
export DEEPSEEK_API_KEY=sk-xxxxx   # Windows: set DEEPSEEK_API_KEY=sk-xxxxx
```

两个 key 可以都配上，然后在界面上按功能挑模型（见下）。不配置对应环境变量的话，定时搜索、待审核列表这些功能照常可用，只是用到那家 API 的功能会报错提示未设置。

## 选用哪个模型

七块用到 AI 的功能可以**各配各的模型**，在「更多 → 设置 → AI 模型与自动分析设置」里各有一个下拉：

| 功能位 | 管什么 | 建议 |
| --- | --- | --- |
| JD 匹配分析 | 每条职位的匹配度计算、公司国籍分类 | 每条职位都要跑一次，量大，选便宜的（DeepSeek） |
| 定制简历 / Cover Letter | 按需生成的定制简历改写方案 + cover letter | 决定要投了才生成，质量优先 |
| 面试准备 | 单条职位的准备材料 | 生成一次要看很久，选质量好的 |
| 通用题库 | 题库 AI 起草 + 跟 AI 对话 | 同上 |
| 简历体检 | 整份简历的诊断 + 逐段改写建议 | 同上，一份简历一般只跑几次 |
| 职位 AI 对话 | 职位详情页的自由问答 | 追问频繁，选便宜的 |
| 偏好档案 | 把忽略原因总结成偏好档案 | 攒够阈值才跑一次，频率很低，随便选 |

可选：**Claude Sonnet 5**（质量最好，约 $3/$15 每百万 token）、**Claude Haiku 4.5**（快且便宜，约 $1/$5）、**DeepSeek V4 Pro**（推理模型，最省钱）、**DeepSeek V4 Flash**（更快更便宜，质量略低）。选「跟随全局设置」就用 `config.json` 里的 `llm_provider` + 对应模型名。

面试页、职位详情页和「我的简历」页的顶栏也各有一个同样的下拉，直接管这一页用的模型，不用绕回设置页。**下拉是选了就存的**，不用点「保存设置」；改动在**下一次**生成/对话时生效，正在后台跑的那一次用的还是切换前的模型。

## 运行

```bash
python app.py
```

打开浏览器访问 `http://127.0.0.1:5050`。

首次打开后：

1. **先点顶栏的「我的简历」上传一份 `.docx` 简历**（详见下面「我的简历怎么用」）。不传的话第 2 步以后的 AI 功能都用不了。
2. 回到主页，打开「更多 → 设置」，填写关键词（每行一个，如 `Senior Product Manager` / `AI产品经理`）。
3. 填写想搜索的城市（每行一个；留空一行表示不限地点/远程）。
4. 可选：填写「重点关注公司」（每行一个公司名，如 `Amazon` / `HSBC`）。普通关键词搜索受 LinkedIn 排名和结果条数上限影响，不保证这些公司的新职位每次都能被搜到；填了之后每次搜索会额外对每家公司单独跑一次 LinkedIn 定向搜索（沿用上面的关键词，不用重复填），不受排名影响。保存时会自动把公司名解析成 LinkedIn 内部 ID，解析结果显示在输入框下方；解析失败会提示检查拼写。公司别配太多，5~8 家为宜——额外请求量 = 公司数 × 关键词数。
5. 填写 `JD匹配追踪表.xlsx` 的完整本地路径（留空则默认 `~/Downloads/JD匹配追踪表.xlsx`）——既用于去重，也是自动分析结果的写入目标，和 `jd-resume-matcher` 技能共用同一份文件。
6. 填写定制简历想保存到哪个目录（留空则跟上传的简历同目录，也就是项目下的 `resumes/`）。
7. 设置每天自动搜索的时间；旁边的"开启"勾选框可以关闭每天定时任务（关闭后不会自动跑，仍可随时手动点"智能抓取"）。
8. 点击"保存设置"。
9. 想立刻测试搜索效果，点"智能抓取"。

只要这个程序开着（`python app.py` 进程存活）且"开启"勾选框没关，就会按设置的时间每天自动跑一次，把新职位加进"待审核新职位"列表。

## 我的简历怎么用

顶栏「我的简历」（新标签页打开 `/resume`）。这一页是整条流水线的地基——匹配分析、面试准备、题库起草读的都是这里的简历。

**上传 / 替换**：拖到虚线框里，或者点一下选文件。**只收 `.docx`**：定制简历和优化版都是按段落改写你的原文件、保留你自己的字体和排版，PDF 没有这个结构，所以收了也做不到（用 Word 另存为 .docx 再传即可）。文件只存在你自己这台机器上（项目目录下的 `resumes/`，已加进 `.gitignore`），不会上传到任何第三方。上传后能看到解析出多少个段落——如果这个数字明显偏小，多半是简历内容放在文本框或图片里，程序读不到，建议改成普通段落。原件随时可以下载回来，也可以删除（删了之后 AI 功能会停用到你重新传一份为止）。

**AI 体检**：点「开始体检」，对整份简历做一次不针对具体职位的诊断，一般三十秒左右，在后台跑，跳去别的页面不会中断；跑完之前如果你已经离开了这一页，首页统计卡片下方的待办清单会出现「体检已给出建议，去优化简历」提醒你回来看。目标岗位方向直接取「设置」里的搜索关键词，不用再填一遍。给出：

- 四个维度的评分——结构与排版 / 成果说服力 / 关键词覆盖 / 表达质量，以及总体评分
- 写得好的地方（具体指出是哪一段的什么写法好）
- 问题清单，按严重 / 中等 / 建议分色排序
- 关键词覆盖：对照目标岗位，哪些能力你已经写出来了、哪些**你可能具备但没写**

**逐段改写建议 → 优化版 docx**：体检结果下面是三到八条具体改写，每条都有"原文 / 改写 / 为什么这么改"。默认全选，取消掉你不认同的，点「生成优化版 docx」下载。**改写只基于简历里真实存在的经历和数据**，不会替你编经历或造数字；遇到"这里缺个数据"的地方，它会留一句"（此处建议补充具体数字：…）"让你自己填。生成的是新文件，原件不动。

换了简历之后，之前那份体检结论会标上「简历已更新，建议重新体检」——旧结论里的段落位置对不上新文件了，照着改会改错段落。

**各职位的定制简历**：页面最下面列出 AI 匹配分析给各个职位生成过的定制简历（公司 / 职位 / 匹配度 / 下载）。以前这些文件只在职位详情弹窗里露一面，关掉就找不着了。文件被移走或删掉的会标成"文件已丢失"，而不是给一个点了才报错的下载按钮。

## 筛选、刷新、撤销

职位列表上有四套可以任意叠加的筛选：顶部统计卡片（待审核 / 已收藏 / 已忽略三选一，再点一次回到全部；「重点关注」是独立开关，可以跟前三者叠加）、"🌍 外企 / 🇨🇳 国内公司 / 全部"、"投递状态"chip，外加一个搜索框。

投递状态的筛选 chip 只放常用的几档（全部 / 待投 / 已投递 / 面试中 / Offer）。「已拒绝」「已婉拒」是流程走完后的归档态，翻看频率低，就不占筛选栏的位置了——**职位卡片上的投递状态下拉仍然可以标记这两个状态**，历史数据也都在。

职位卡片上还有标签（见「标签怎么用」），工具栏对应一组标签筛选 chip，单选、再点一次取消。

**筛选状态会写进地址栏**（`?status=&origin=&app=&starred=&tag=&q=`），所以刷新页面不会丢，也可以把某个常用组合直接存成书签。不带参数打开 `/` 时默认是"待审核 + 全部公司"。空列表会明确区分"库里还没有任何职位"和"库里有 N 条、都被当前筛选挡住了"，后者带一个"清除全部筛选"按钮。

工具栏右侧的**"刷新"按钮**重新拉一次职位列表和运行记录。批量重新获取JD、识别公司国籍、批量 AI 分析、批量生成材料这些任务都在后台跑、跑完没有通知，点这里看结果；比按 F5 快，也不会重载整个页面。

点"忽略"（✗）之后，右下角的提示里有一个**"撤销"**按钮，6 秒内点它可以把职位改回原来的状态——这个操作没有二次确认弹窗，因为它是每天要点几十次的动作。职位详情页顶部也有一个「忽略」按钮，走同一条路（看完详情决定不投，不用先返回列表再去找那张卡片）。所有提示都可以点右上角的 × 手动关掉。**如果这条职位正在 AI 分析中就被标记忽略，分析会被中断、结果不会保留，但不会影响批次里其它职位。**

忽略生效之后会弹一个**可跳过**的小弹窗问你原因，见下面「忽略原因收集 → 偏好档案怎么用」。

深色模式的切换开关在「更多 → 设置 → 外观」里。没手动选过就跟随系统。

## 每日任务清单怎么用

首页统计卡片下方是一块可勾选的清单，把散落各处的"该干什么"收进一处：今日抓取（漏斗）、N 条待审核、K 条已收藏还没投递、J 条投递超过 7 天该跟进了、简历要是还没体检过也会提醒一句、体检给出建议后还没生成优化版也会提醒一句（这条会一直留着，直到你真的生成了优化版，或者自己主动点掉——不会因为跨了一天就自己消失）。点文案（不是勾选框）会直接跳到对应的筛选视图或页面。

清单默认展开，每次刷新页面都会先摊开给你看一眼；点标题栏（"今日待办"那一行）可以收起/展开，收起后只剩一行标题+条数，不占地方，收起状态不会被记住，下次刷新还是展开的。

- 除了"该跟进""该体检""体检给出建议后还没优化"这三条，其它几项**勾掉只是今天不想再看到**，不会改变任何数据——它们的数字永远是按当前库里的真实状态现算的，明天打开又会按新状态重新出现。"体检给出建议后还没优化"这条勾掉是长期生效的，直到下次重新体检出新结果才会恢复提醒。
- 底部有个"+ 添加一条待办"输入框，可以记点清单没自动覆盖到的事，这个是真正存起来的，勾掉即删除。
- "投递超过 7 天该跟进"这一项依赖投递状态**变成「已投递」那一刻**记的时间戳；如果是很早以前手动改成"已投递"的历史数据（这个功能上线之前），没有时间戳就不会被计入，不会瞎猜。

## 忽略原因收集 → 偏好档案怎么用

标记"忽略"之后会弹一个小窗，问要不要说说为什么不考虑这条职位——预设了薪资不符 / 职能不对 / 公司不感兴趣 / 地点 / 行业 / 层级不匹配几个标签（可多选），也能自己写几句，全都是**选填**，点"跳过"或直接关掉都行，不影响忽略本身已经生效。

攒够 5 条新原因后，程序会在后台自动调一次 LLM，把这些原因总结成一段"偏好档案"，之后每次做 JD 匹配分析都会参考它（比如反复因为薪资不符被忽略，新职位薪资明显偏低时匹配度可能会被酌情调低——不会仅凭一次不完全匹配就直接判死）。当前的偏好档案内容在「更多 → 设置 → 偏好档案」里能看到，也有"立即重新生成"按钮不等攒够就手动触发一次。

已经忽略过、但还没留过原因的历史职位（比如这个功能上线之前就忽略掉的），卡片上会多一个"记录忽略原因"的小图标，可以随时回去补一笔——**越早补全，偏好档案的参考价值越大**。

## 手动添加职位链接怎么用

按关键词 × 城市的自动搜索总有漏的——标题换个措辞就对不上关键词、城市没配、或者是你在 LinkedIn 推荐流里刷到、朋友直接转给你的一条。首页导语行的**「添加链接」**按钮就是给这些职位准备的入口：

1. 点「添加链接」，把 LinkedIn 职位链接贴进文本框，**每行一条，一次最多 20 条**。从职位详情页地址栏复制的（`.../jobs/view/4123456789/`）和从搜索/推荐页复制的（`...?currentJobId=4123456789`）都认。
2. 点「抓取并入库」，等结果——不是"已在后台开始"就完事，会**逐条**告诉你每条链接的下场：已入库（带一个直接查看这条职位的链接）/ 已存在（库里或追踪表里已经有了）/ 失败（附原因）。
3. 入库的职位落在「待审核」里，**后面的流程跟自动搜索抓回来的完全一样**：自动排队 AI 匹配分析、识别公司国籍，之后照常生成材料、准备面试。

几点值得知道的：

- **不会被"不相关"筛掉**。自动搜索抓回来的职位在分析前有一道标题/地点粗筛（跟你配置的关键词、城市不沾边的不花钱分析），手动贴的链接**不走这道筛选**——是你自己挑的，程序没有立场替你否掉。所以贴一条深圳的岗、或者标题措辞完全不同的岗，都会正常分析。
- **抓不到时会自动改用浏览器**。先用访客身份（不登录）抓，遇到限流、或这条职位本来就要登录才可见时，自动改用你在「LinkedIn Easy Apply」那一步登录过的浏览器再抓一次。这种情况慢一些（要起一次浏览器），也要求那个登录态还有效；如果 Easy Apply 的浏览器窗口正开着，profile 被占用，这次兜底会失败并如实报错。没设置过 Easy Apply 登录的话，只有访客身份这一级可用。
- 抓取是**同步**的，贴了好几条又都要走浏览器兜底时，按钮会转圈转一会儿（十几秒到一两分钟），这期间别关弹窗。
- 目前**只支持 LinkedIn 链接**，贴 Indeed 或别的站点会明确报"认不出这是哪条 LinkedIn 职位"。
- 极少数情况下能拿到职位名和公司、但拿不到 JD 正文，这条职位仍会入库并标注"没抓到 JD 正文"——它不会自动分析（没有正文可分析），用工具栏的「全部重新获取JD」补一次即可。

## 自动分析怎么用

每次搜索（定时触发，或点"立即搜索一次"）找到新职位后，会在后台自动依次分析所有还没分析成功过的"待审核"职位，不需要手动点击：

- 程序会把职位的 JD 正文（搜索时已经抓到）和**你在「我的简历」上传的那份简历**一起发给配置的 LLM API，按 `jd-resume-matcher` 技能里定义的双因子模型（认知要求匹配度50% + 工作内容匹配度50%）计算总体匹配度。还没上传简历的话，点分析会提示先去上传，不会留下失败记录。这一步**只算匹配度，不生成定制简历/cover letter**——那一步改成按需触发，见「定制简历 / Cover Letter 怎么生成」。
- 结果会写入追踪表 xlsx 新的一行（在最上面），包含对比表全部字段。分析完成的职位点卡片（非标题、非按钮区域）即可跳转到这条职位的**详情页**看完整分析结论；卡片上的职位名称可以直接点击，新标签页跳转到原职位发布页，详情页顶部也有同样的链接。未分析完成的职位卡片不可点击。
- 分析完成后该职位在网页列表里会显示匹配度百分比；失败会显示"分析失败"，鼠标悬停能看到具体错误信息（比如 API key 没配、余额不足），程序下次搜索/启动时会自动重试。
- 也可以对某条职位点"AI 分析"手动立刻触发一次（不用等下次自动跑），比如想马上重试一个失败的。
- 页面最顶部（品牌栏右侧）有一个"AI分析"按钮，点击会对"待审核"里**所有**还没分析成功过的职位发起批量分析，不限于最近一次搜索新增的，也包括历史积压——想清理老早搜到、一直没轮到自动分析的旧记录时用这个。点下去按钮会变成红色的"停止分析"，再点一次会**立即**中止批次：页面马上恢复成"AI分析"、剩余排队的职位恢复成未分析状态，不再继续分析下一条；如果点停止的时候恰好有一条正在分析，这条职位调用LLM的网络请求技术上没法从外部强行掐断，会在后台默默跑完，但跑完的结果会被直接丢弃（不写库、不写追踪表），跟没分析过一样，之后需要的话可以再手动点它的"AI 分析"重新跑一次——也就是说这条被中断的职位那次LLM调用的费用已经产生但结果不会保留，属于中途叫停必然的代价。批次自然跑完（没有被中途停止）后按钮也会自动变回"AI分析"。注意积压条数多的话点一次可能触发几十上百次 LLM 调用，会产生相应的 API 费用，建议先看一眼"待审核"有多少条心里有数。
- JD正文没抓到的职位（来源站点没返回描述、被限流等），会直接跳过AI分析、不调用LLM——不会白花钱去分析一段空内容。这类职位的卡片上"AI 分析"按钮会换成"重新获取"，点击重新抓一次JD正文，抓到了会自动接着跑一次分析，页面会自动轮询、跑完自动刷新显示结果（不用自己再点"刷新"，一般几十秒到一两分钟，最长等4分钟，超时会提示"仍在后台处理中"，之后手动点刷新就能看到）；顶部工具栏的"全部重新获取JD"按钮可以批量处理"待审核"里所有JD缺失的职位（后台进行，处理条数多的话会比较慢，需要自己点"刷新"查看结果，不会自动刷新）。如果这条职位现在已经不在原来搜索关键词/城市的最新结果里了，重新获取可能会失败，可以再点一次重试。

批量自动分析在后台线程里跑，不会卡住"立即搜索一次"按钮或页面其他操作，而且是**逐条串行**分析的，不会同时并发跑多条（主要顾虑是同时写 `JD匹配追踪表.xlsx` 容易冲突、LLM API 也有速率限制）；每条大概几十秒到一两分钟（取决于 LLM 和 JD 正文长度），新增职位多的话整个批次可能要等几分钟才能都跑完。批次里正在跑的那一条，卡片按钮显示禁用态的"AI分析中…"；还没轮到的其它条显示"排队中…"；页面会每隔几秒自动轮询刷新，不需要手动点"刷新"就能看到匹配度陆续出现。批次跑得比较久的情况下（比如顶部"AI分析"按钮清理历史积压），如果排在后面还没轮到的职位在等待期间被手动标记"已忽略"，轮到它时会自动跳过、不再花钱分析。
- 已经生成定制简历/cover letter 的职位，卡片公司名那一行会出现"📄 定制简历"（点击在新标签页打开/下载 docx 文件）和"✉️ Cover Letter"（点击跳转到详情页查看全文）链接。

AI 分析时还会顺带判断该公司是外企（总部在中国大陆以外，含在华子公司/办公室）还是中国大陆本土公司，职位卡片上会显示"🌍 外企"或"🇨🇳 中国公司"徽章；这个判断没有可靠的数据源，全靠 LLM 自身知识+JD 内容线索，不保证准确，判断不出的（比如没听说过的小公司）不显示徽章。职位列表页顶部工具栏有一组"🌍 外企 / 🇨🇳 国内公司 / 全部"筛选，**默认选中"全部"**。"外企"筛选会隐藏已判定为"中国大陆本土公司"的职位，但*还没分析完成*或*AI 判断不出来*的职位仍会正常显示，不会被误藏；只想看国内公司就切到"国内公司"。

## 定制简历 / Cover Letter 怎么生成

分析完成之后，觉得这条职位值得投了，再去生成定制材料——不用等，也不用先收藏：

- **单条生成**：进这条职位的详情页（点卡片跳转），左栏最下面有「生成定制简历 + Cover Letter」按钮，点一下后台开始生成（30-60 秒），完成后自动刷新，能看到定制简历下载链接和 cover letter 全文；已经生成过的这里会变成「重新生成」。
- **批量生成**：职位列表页工具栏的"批量生成材料"按钮，对**当前筛选出来的职位**生效——先调好筛选（比如只看"已收藏"），再点这个按钮，会弹一次确认框告诉你这次要处理多少条。已经生成过材料的职位会被自动跳过，不会重复烧钱；正在分析中或已经在排队生成材料的也会跳过。
- 生成用的是简历原文 + 之前的匹配分析结论（技能缺口、未达标的任职要求），定制简历只改写措辞、突出相关经验，不会编造未发生的经历；cover letter 会在存在明显能力缺口时主动坦诚说明，给出可迁移能力的说法。
- 还没跑过 AI 分析的职位不能生成材料（按钮会提示"请先完成 AI 分析"）。

## 重点关注怎么用

每条职位卡片右侧操作区最左边有一个★星标按钮，点一下把这条职位标记为"重点关注"（星变成实心金色），再点一次取消。它跟审核状态（新/已收藏/已忽略）、投递状态都是独立的，标不标星不会改变职位的其它状态，还在"待审核"阶段就可以先标上；"已忽略"的卡片也保留这个按钮，方便随时取消标记。

顶部第三张统计卡片就是"重点关注"，显示当前标了星的总数，点一下只看这些职位、再点一次取消。它是独立开关，可以跟公司国籍、投递状态、以及另外三张卡片的审核状态筛选任意叠加（一条职位可以既"已收藏"又"重点关注"，所以这两个数字本来就会重叠）。

## 标签怎么用

给职位打自定义分类标签，跟审核状态、重点关注、投递状态都是独立维度。职位卡片操作区有一个 🏷️ 按钮（职位详情页也有同样的入口），点开一个小窗口：

- 已经打上的标签显示成一排徽章，点每个后面的 × 移除。
- 预设四个常用标签可以直接点选：`AI`、`ML`、`remote`、`tech`。
- 也可以在下面的输入框敲自己的标签，回车或点"添加"（标签文字不能包含逗号，最长 20 个字符，一条职位最多 10 个）。
- 点"保存"生效。

职位列表工具栏会自动列出预设标签 + 库里所有职位实际在用的自定义标签，做成一排筛选 chip，单选、再点一次取消，可以跟其它筛选任意叠加，筛选状态也会写进地址栏（`?tag=`）。

## 投递状态跟踪怎么用

已收藏的职位卡片上有一个下拉框，可以手动标记这条职位当前的投递状态：待投 / 已投递 / 面试中 / 已拒绝 / Offer / 已婉拒，默认是"待投"。这个状态跟审核状态（新/已收藏/已忽略）是两回事，互不影响，纯手动维护，程序不会自动帮你改。"待审核"和"已忽略"的卡片不显示这个下拉框（还没决定要不要投的阶段用不上），把职位标记"已收藏"后就会出现。工具栏有对应的筛选 chip，可以按投递状态筛职位列表看。

## 职位详情页：AI 对话 + 备注怎么用

点开一条已经分析过的职位卡片，会跳转到它的详情页（`/jobs/<id>`）：左边是完整的匹配分析结论（公司简介、职位内容、任职要求、技能匹配、定制简历/Cover Letter），右边是两块常驻的侧栏。

**AI 对话**：右上角的对话框可以就着这条职位自由提问——"这家公司最近有什么新闻""这个职级大概对应我现在的什么水平""JD 里这句话具体什么意思"。AI 看得到这条职位的 JD、之前的匹配分析结论、以及你的简历。**对话不会保存**，刷新页面就清空了（跟通用题库的"跟 AI 聊聊这题"是同一个设计），值得留下的内容自己点「📌 记进备注」存一下。

**备注**：右下角是这条职位的备注列表，最新的排最上面，每条标着来源——`[AI]` 是从对话里记下来的，`[手写]` 是自己写的。可以直接在下面的输入框手写一条，也可以随时删除某一条（删除前会确认，因为删了找不回来）。备注是这条职位唯一"记事本"式的地方，把职位投递状态改成「面试中」之后，`/jobs/<id>/interview` 面试准备页也会把这些备注原样列出来，方便面试前扫一眼"之前查过什么"（加/删还是要回详情页操作）。

## 面试准备怎么用

**自动生成**：把某条职位的投递状态改成「面试中」，程序会在后台自动生成一份针对这家公司/这个岗位的面试准备材料，用 `deepseek-v4-pro` 实测要 3-5 分钟（这类推理模型光内部推理就要花掉两三分钟，正文才开始写）。生成期间职位卡片上会显示"🎤 准备中…"，好了变成可点击的"🎤 面试准备"徽章，点它直接跳到材料页面。

同一条职位只会自动生成一次——反复切换投递状态不会重复调用 LLM 重复花钱。上次生成失败的（比如网络抖动）不算数，下次切到「面试中」会自动再试。

**在哪看**：面试准备是一个**独立页面** `/jobs/<职位id>/interview`，两个入口——职位卡片上的"🎤 面试准备"徽章，或者进这条职位的详情页、点右上角「🎤 面试准备 →」。

做成独立页面而不是弹窗，是因为这份材料是面试前坐下来看半小时的东西：可以单独开一个浏览器标签页一直挂着、可以直接收藏 URL、刷新或切走再回来都不影响（生成中的轮询也不会断）。职位详情页（匹配分析 + AI 对话 + 备注）出于同样的理由也是独立页面。

材料分四块：

- **公司 / 业务背景**：主营业务、这个岗位在组织里的位置、面试里可以主动聊的业务痛点、能显示你做过功课的切入点。
- **预测面试题**（10-15 道）：按"行为面 / 业务领域 / 技术方法论 / 职业动机"分组，点开每道题看"为什么会问这题"、答题要点（行为题按情境-任务-行动-结果组织）、以及简历里可以直接引用的那段经历或数字。
- **缺口应对话术**：对应「匹配分析」里标红的未达标要求，每条给出面试官大概率怎么问、建议怎么答（坦诚承认边界 + 可迁移经历 + 补齐计划，不会教你编造经历）、以及简历里能拿来顶的最接近的经历。这一块的输入直接来自匹配分析已经算好的结论，所以两边看到的缺口是同一套，不会自相矛盾。
- **反问面试官 + 面试前准备清单**。

**重新生成**：面试准备页面上方有「🔄 重新生成」按钮，旁边可以填一个轮次标签（比如"二面"）。每生成一份都会保留，有两份以上时左上角会出现版本下拉，可以切回之前那份对照看；不想留的可以点「删除这份」。

**注意**：

- 这条职位必须有 JD 正文才能生成（没有的话先点卡片上的「重新获取」抓一次 JD）。
- 答题要点是基于你简历里真实存在的经历和数据生成的，prompt 里明确禁止编造经历、夸大数据——但 LLM 仍可能理解偏差，**用之前自己过一遍**，尤其是引用了具体数字的地方。
- 公司背景那一块是 LLM 基于自身知识写的，可能过时或不准，重要信息建议自己再核实一次。
- 生成失败不会影响投递状态本身（状态照常改成"面试中"），失败原因会显示在面试准备页面上，点「重新生成」重试即可。

## 通用面试题库怎么用

上面那份是针对某一条职位的。而"自我介绍""为什么离开上一家""职业规划"这类问题每场面试都会遇到，跟具体公司无关——这些放在**独立页面 `/interview`**，准备一次长期复用。首页导语行右侧的「面试题库」按钮和面试准备页的「🎤 通用题库 ↗」都会**新开一个标签页**，方便一直挂着背题、不打断原来那一页。

四个板块，**每道题的答案都有中文和 English 两版**（外企面试用得上，也逼自己把英文说法先想清楚）：

- **自我介绍**：60-90 秒口播稿。固定一条。
- **STAR 故事库**：从简历里提炼的 3-5 个能反复复用的完整故事（从0到1、跨部门协作、冲突处理、数据驱动决策、失败复盘），固定按「情境 / 任务 / 行动 / 结果」四段写。面试时大部分行为题都能从这几个故事里取材。
- **讲述过往工作**：简历上**每一段工作经历各 3-4 题**——这段负责什么、最有代表性的成果、最大的挑战怎么解决的、为什么离开。题目里会带上公司名，多段经历一眼能分清。
- **通用问题**：8-12 道高频题（离职原因、职业规划、优缺点、讲一次失败、期望薪资怎么谈等）。

答案都是**分段**的（段落之间空一行），输入框高度跟着内容自动变，不会出现"在一个小框里滚动一大坨文字"。

**找题**：题目**默认收起，只显示标题**，点标题那一行展开/收起；顶部有「全部展开 / 全部收起」。左边是目录，列出四个板块和每一道题，点某题直接滚过去并自动展开。

**怎么用**：第一次点右上角「✨ AI 起草 / 补充」，程序会根据你的基础简历和设置里的搜索关键词（当成你在找的岗位方向）生成一份初稿。起草分**四段依次进行**（自我介绍 → STAR 故事库 → 讲述过往工作 → 通用问题），每段跑完立刻出现在页面上，全部跑完用 `deepseek-v4-pro` 实测要 5-10 分钟——不用干等着，先到的那段就可以开始改。某一段失败不影响其它段，页面上会红字说明是哪一段挂了，再点一次只补这几段。

**改过的答案不会被覆盖**：每条右上角有徽章标着「AI 初稿」还是「已自定义」。再点「AI 起草 / 补充」时，只有还是「AI 初稿」的条目会被更新，你改过的一律跳过，手动加的题也自动受保护；已有的题一条都不会被删掉。所以想补充新问题的时候可以放心再点，不会丢东西。

**重复点「AI 起草 / 补充」不会堆出重复题**：判断"这道题是不是已经有了"时会忽略空格和标点差异，而且起草时会把已有题目的原文一起交给模型、要求同一个意思就照抄原文措辞。所以第二次起草是更新原有条目 + 补上真正的新题，不会出现「未来3-5年你的职业规划是什么？」和「未来 3-5 年职业规划是什么？」并存这种情况。偶尔仍可能漏进一条措辞相近的（模型没完全照抄），用那条的「删除」清掉即可。

**「删除」是真删**：把这道题连同你写的中英文答案从数据库里永久删掉，无法恢复。另外注意，如果删的是 AI 出的题，下次点「AI 起草 / 补充」很可能又会生成回来（判重只看题库里现存的题，不记得你删过什么）；手动加的题删掉后不会自己回来。

**自己加题**：点板块标题右边的 `+`，下面会出现一个输入框，写完问题按回车（或点「添加」）即可，Esc 取消。新加的题会自动展开等你写答案，并且默认就受保护、不会被之后的 AI 起草覆盖。自我介绍固定一条，所以那一块没有 `+`。

### 跟 AI 聊着改答案

AI 初稿变成"我自己的说法"这一步，不用全靠手打：

**改某一道题**：点那道题下面的「💬 跟 AI 聊聊这题」展开对话框，说清哪里不满意就行——"太长了，压到 60 秒"、"把 XX 项目的数据放前面"、"这段听起来像套话，换成我自己的经历"。AI 看得到你的简历、这道题、以及这一版答案的当前内容，每轮回你一句"我改了什么"，外加**一整版改写好的答案**。满意就点「用这版替换…答案」把它填进上面的输入框，不满意就接着聊。

两个刻意的设计：

- **点了「采用」只是填进输入框，还要再点「保存」才真的存进数据库**。什么时候覆盖掉你原来的答案，始终由你决定；聊崩了也毁不掉已经写好的东西。
- 对话框上方可以切「中文 / English」，**一次只改一版**。切换语言不会清空对话——前几轮聊出来的共识（哪里啰嗦、要突出什么）对另一版同样成立。

**整体检查**：顶栏的「💬 题库助手」打开右侧对话栏，它看得到整个题库，负责挑跨题目的毛病——"我这几个 STAR 故事有没有在讲同一件事"、"按我找的岗位方向还缺哪些常见题"、"哪几题答得最空"。它**只给建议、不直接改答案**（改完也不知道该回填哪一条），指出问题后你再去那道题自己的对话框里改。

**对话记录只存在浏览器里**，刷新页面就没了（答案本身已经存进数据库，不会丢）。聊得太久的话只有最近 20 条会带给模型，省 token。

## LinkedIn Easy Apply 半自动投递怎么用

只支持 LinkedIn 的 Easy Apply（站内一键申请）职位，且这条职位必须已经生成过定制简历（`resume_path` 不为空）才会出现"Easy Apply"按钮；Indeed 或需要跳转到公司官网申请的 LinkedIn 职位不支持。

**首次使用前的准备**：

```bash
pip install -r requirements.txt   # 会装 Playwright
playwright install chrome         # 如果本机没有 Chrome，代码会退而用 Edge（channel="msedge"），不需要额外装
python -c "from easy_apply import ensure_logged_in; ensure_logged_in()"
```

最后一条命令会弹出一个真实可见的浏览器窗口停在 LinkedIn 登录页，手动登录一次即可（账号密码不会被程序读取或保存，只有登录后的 session cookie 会保存在本地 `.playwright_profile/linkedin/`，已加入 `.gitignore`，不会被提交到 git、也不要把这个目录发给别人）。登录态之后会一直复用，除非 LinkedIn 要求重新验证（这种情况下 Easy Apply 会报错提示"登录态可能已失效"，重新跑一次上面这条命令再登录即可）。

**建议先在"更多 → 设置"里填一份"Easy Apply 自动回答设置"**：工作签证/期望薪资/入职时间三个高频字段，加上"其它常见问题"文本框（每行一条，格式必须是 `问题关键词=答案`，注意是英文等号——不要用问题本身常带的冒号，格式不对的行保存时会有 toast 提示哪几行没识别出来）。这份资料决定了自动化能替你答多少题、走多远；不填也能用，只是每一步筛选问题都会停下来等你手动填。

**使用**：点击职位卡片上的"Easy Apply"按钮后，程序会：

1. 打开一个真实可见的浏览器窗口，导航到这条职位的 LinkedIn 页面。
2. 找到并点击"申请"/"快速申请"/"Easy Apply"按钮（LinkedIn 中文界面下这个按钮的文字不固定，代码同时匹配几种已知写法）。
3. 尽力自动填写：上传定制简历、粘贴 cover letter（找到匹配的输入框才会填）。
4. **自动回答设置页配置过的筛选问题，并自动点"下一步"翻页**——单选题按选项文字匹配你配置的答案，文本/下拉题按问题关键词匹配；LinkedIn 自动带出的资料（姓名/邮箱/电话等）已经有值的字段不会被覆盖。
5. **遇到没配置过答案的问题、或者已经翻到最后确认页（没有"下一步"按钮了）就停下**，浏览器窗口保持打开、不会自动关闭。**最终的检查和提交必须由你自己切换到那个窗口手动完成**——程序代码里没有、也不会有点击最终"提交申请"的逻辑，即使当场口头要求它继续点也不会照做，这是刻意的设计边界，详见 [spec/mission.md](spec/mission.md#投递自动化的边界2026-08-16-上线2026-08-16-修订)。
6. 同一时间只能有一个 Easy Apply 窗口在跑（Playwright 对同一份登录态 profile 是独占锁），处理完当前这条（提交或关闭窗口）之后才能开始下一条。

失败/停在半路的常见原因：登录态失效（重新登录）、这条职位其实不支持站内 Easy Apply（会跳到外部公司官网）、页面结构变化导致按钮/字段找不到（LinkedIn 会不定期调整前端，选择器可能需要跟着更新）、遇到没配置答案的问题、遇到用非标准写法（没有 `<legend>`）呈现的问题——这类问题即使配置了关键词也匹配不上，只能每次人工填。

改完代码后在项目根目录跑：

```bash

```

所有套件用临时数据库 + 临时 config（简历上传也落在临时目录），LLM 调用全程 mock，**不会产生真实 API 费用，也不会碰你的 `jobs.db`、`config.json` 和 `resumes/`**。最后还会用 `node --check` 检查各个 JS 文件的语法（没装 node 会报缺少可执行文件）。

单独跑某一个套件也可以：`.venv/Scripts/python.exe tests/test_bank.py`。

## 已知限制

- **"只看外企"判断不保证准确**：没有权威的公司国籍数据源，全靠 AI 根据公司名称和 JD 内容自行判断，可能出错（比如把外资在华子公司误判成本土公司，或反之），用"外企"筛选时建议偶尔切回"全部"确认没有漏看感兴趣的职位。
- **只能有一份简历**：没有多简历/多版本管理，想投不同方向要自己换上传的文件；换了之后已有的体检结论会标记过期，需要重新体检。
- **简历只支持 `.docx`**：PDF、纯文本粘贴都不支持，因为定制简历和优化版都要按段落索引改写原文件、保留排版。
- **生成的"优化版"固定覆盖同一个文件**（`resumes/optimized.docx`），不保留历史版本；原件一直都在，要回溯就从原件重新生成。
- **Easy Apply 的按钮/字段选择器可能因 LinkedIn 前端改版而失效**：目前的选择器是根据实测调整出来的（中文界面下 Easy Apply 按钮文字见过"申请""快速申请"两种写法），不是官方稳定接口，LinkedIn 改版后可能需要重新调整 `easy_apply.py`。
- **职位 AI 对话不落库**：刷新页面、关掉标签页就清空，值得留的内容要自己点「记进备注」；多个标签页同时开着同一条职位的详情页也不共享对话。
- **批量生成材料一次性可能触发很多次 LLM 调用**：会产生相应的 API 费用，点之前先看一眼筛选下的条数。

## 文件说明

- `app.py`：Flask 服务 + API。
- `scraper.py`：单次搜索逻辑（调用 python-jobspy，按关键词×城市循环，抓取JD正文，去重后入库；另外对「重点关注公司」列表里已解析成功的每家公司额外跑一次 `linkedin_company_ids` 定向搜索，沿用同一套去重/入库逻辑）。
- `job_link.py`：手动贴 LinkedIn 职位链接入库（解析链接里的 job id、访客页抓取、抓不到时用已登录浏览器兜底、去重后入库）。跟 `scraper.py` 分开，因为 jobspy 没有"按链接取单条职位"的接口。
- `linkedin_company.py`：把「重点关注公司」的公司名解析成 LinkedIn 数字公司 ID（访客页优先，抓不到再退化到已登录浏览器兜底），供 `scraper.py` 的定向搜索使用。跟 `job_link.py` 抓取骨架相同但目标页面不同（公司主页 vs 职位详情页），没有直接复用解析函数。
- `scheduler.py`：APScheduler 定时任务。
- `models.py`：SQLite 存储（`jobs.db`，运行后自动生成，已加入 .gitignore）。
- `tracker_xlsx.py`：只读追踪表工具，用于搜索阶段的去重判断。
- `tracker_utils.py`：追踪表写入工具（复用自 `jd-resume-matcher` 技能的 `scripts/tracker_utils.py`，保证格式/列结构完全一致）。
- `resume_docx.py`：读取基础简历文本、按段落索引生成定制版/优化版简历 docx。
- `resume_store.py`：用户上传的基础简历的唯一入口——校验（只收 .docx、≤10MB、必须真能解析出正文）、落盘到 `resumes/`、指纹、回写 `base_resume_path`。
- `resume_review.py`：简历体检的 prompt + 结果归一化（四维评分、问题清单、逐段改写建议）。
- `preference_profile.py`：把忽略职位时留的原因总结成一段"偏好档案"的 prompt + LLM 调用，不碰数据库（编排在 `pipeline.py` 的 `maybe_refresh_preference_profile`）。
- `llm.py`：统一的 LLM 调用层，屏蔽 Anthropic / DeepSeek 的接口差异（单轮/多轮对话、system prompt、max_tokens），`analyzer.py`、`interview.py`、`resume_review.py`、`job_chat.py`、`preference_profile.py` 共用。
- `analyzer.py`：JD-简历匹配分析的 prompt（只算匹配度），以及定制简历/cover letter 材料生成的 prompt，解析结果。
- `interview.py`：面试准备（单职位准备材料 + 通用题库）的 prompt 和 LLM 调用（不碰数据库，编排在 `pipeline.py`）。
- `job_chat.py`：职位详情页 AI 对话的 prompt 和调用，不落库。
- `pipeline.py`：把"取JD → 调用analyzer → 写入追踪表 → 更新任务状态"串起来的编排逻辑，以及材料按需生成、面试准备生成的编排。
- `job_state.py`：进程内内存状态（AI分析排队/进行中、材料生成排队/进行中、Easy Apply 启动中/失败、面试准备生成中），不持久化，重启后重新触发即可。
- `easy_apply.py`：LinkedIn Easy Apply 半自动投递的 Playwright 自动化逻辑，跟 `scraper.py`（纯 HTTP 抓取）分开。
- `config.py` / `config.json`：搜索与分析配置（`config.json` 首次运行自动生成，已加入 .gitignore，因为里面可能含本地文件路径）。
- `resumes/`：上传的简历和生成的优化版（运行后自动创建，已加入 .gitignore）。
- `templates/`, `static/`：前端页面。五个页面各自加载自己的脚本：`/`（职位列表，含每日任务清单）用 `common.js` + `app.js`，`/jobs/<id>`（职位详情：匹配分析 + AI对话 + 备注）用 `common.js` + `job_detail.js`，`/resume`（我的简历）用 `common.js` + `resume.js`，`/interview`（通用题库）用 `common.js` + `bank.js`，`/jobs/<id>/interview`（面试准备）用 `common.js` + `interview.js`。`common.js` 是各页面共用的主题切换 / toast / 转义 / 按钮 loading / 模型下拉 / "请先上传简历"引导 / 标签编辑弹窗 / 忽略原因弹窗。
- `tests/`：回归测试。`run_all.py` 是统一入口（每个套件起独立子进程，避免 monkeypatch 互相污染）；`test_prep.py` 覆盖单职位面试准备，`test_bank.py` 覆盖通用题库起草（重点是"用户改过的答案不被重新起草覆盖"），`test_bank_chat.py` 覆盖跟 AI 对话完善答案（重点是"对话绝不写库"），`test_resume.py` 覆盖简历上传校验 / 体检 / 优化版生成 / 没简历时的 409 引导，`test_job_detail.py` 覆盖标签校验 / 备注增删 / 职位对话不落库 / 材料按需生成，`test_dismiss_abort.py` 覆盖"标记忽略中断当前分析但不停整批"，`test_add_by_url.py` 覆盖手动贴链接入库（链接解析、访客页/登录页两套 DOM 的解析、浏览器兜底、去重、以及"手动加的职位不被相关性粗筛挡掉"），`test_preference_profile.py` 覆盖忽略原因收集 / 阈值触发生成 / prompt 注入，`test_checklist.py` 覆盖 `applied_at` 记账 / 超7天待跟进查询 / 自定义待办增删，`test_dedupe_normalize.py` 覆盖去重键归一化（标点/大小写/公司后缀）/ 历史数据迁移的幂等与防撞车 / 同公司相似职位分组不误伤不同产品线，`test_linkedin_company.py` 覆盖公司名解析（访客页/浏览器兜底）/ 保存设置时只重新解析新增或失败的名字 / 定向搜索沿用现有关键词且照常走去重，`test_frontend.py` 对五个页面的模板/JS/CSS 接线做静态断言。
