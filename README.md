# newjob — 每日自动职位搜索 + 自动匹配分析

本地运行的小型 Web 程序：

1. 按你设置的关键字每天定时自动搜索 Indeed 和 LinkedIn 上的新职位，去重后存入"待审核"列表。
2. 待审核列表里的新职位会**自动**调用 LLM（默认 Claude API，也可切换成更便宜的 DeepSeek API）完整走一遍 `jd-resume-matcher` 技能的双因子匹配度分析，写入 `JD匹配追踪表.xlsx`；匹配度≥70%时还会自动生成一份定制简历（docx）和 cover letter。也可以对单条职位点"AI 分析"手动重新触发（比如之前分析失败想立刻重试）。
3. 投递之后把状态改成「面试中」，会**自动**生成一份针对这家公司/这个岗位的面试准备材料（公司背景、预测面试题+答法、缺口应对话术、反问清单）。

## 重要说明 / 边界

- **Indeed**：通过 [python-jobspy](https://github.com/speedyapply/JobSpy) 调用其公开搜索接口抓取。
- **LinkedIn**：LinkedIn 没有公开的职位搜索 API，这里用 python-jobspy 做**非官方抓取**（绕过登录墙）。这可能违反 LinkedIn 的服务条款，存在账号/IP 被限流或封禁的风险。这是你在需求确认时明确选择接受的方案，如果之后想改成"仅手动粘贴 LinkedIn JD"（更保守、零风险），把设置页里 `sites` 的 `linkedin` 去掉即可（或直接编辑 `config.json`）。
- **自动分析会产生 API 调用费用，且是自动触发的**：每次搜索（定时或手动点"立即搜索一次"）**这次新增**的职位会自动分析，不需要你逐条点击；这意味着调用次数/费用直接取决于每次搜索新增多少条职位（关键词×城市组合越多、`results_wanted` 越大，新增越多）。按 DeepSeek 的价格通常每天几毛到几块钱，按 Claude Sonnet 则贵一个数量级左右，具体看每天新增职位数量。为了少花冤枉钱，两种明显不相关的噪音结果会被自动跳过、不调用 LLM：职位标题跟搜索关键词完全不沾边的（比如搜"AI产品经理"混进来的"Clinical Research Lead"），以及职位地点跟设置里的城市列表完全对不上的（比如用"Remote"搜出来的某个不相关国家坐班职位）——这两个粗筛只影响批量自动分析，手动点单条"AI 分析"总会调用。改了城市设置后，之前用旧设置搜到的、现在已经不符合新设置的"待审核"记录不会被自动删除或忽略，只是以后不会再被自动分析，想清理需要自己手动标记忽略。如果想改回"只分析我手动选的职位"，把 `scheduler.py` 里 `_run_job()`、`app.py` 里 `/api/search/run` 和启动时调用 `analyze_pending_jobs()` 的地方去掉即可，不用改其余代码。
- 待审核职位不会因为分析完成就消失或改变筛选状态——它还是"新"，直到你手动标记"已收藏"/"忽略"；分析结果只是让职位卡片多了个匹配度百分比。
- 页面顶部的"待审核"/"已收藏"/"已忽略"三张统计数字卡片可以直接点击，点了哪张就按对应状态筛选下面的职位列表（选中的卡片会高亮）；再点一次已选中的卡片会取消筛选、显示全部状态的职位。
- 只能本地运行（你自己电脑开着的时候才会定时执行）。关机/程序退出后不会补跑错过的当天任务；但程序下次启动时会自动补跑一批之前遗留的、还没分析成功的"新"职位——为了避免历史积压太多导致启动后一次跑很久很久，这个补跑限制了最多条数（`app.py` 里的 `STARTUP_BACKLOG_LIMIT`，默认 5），不会一次性清空所有积压，想加快清理可以改大这个数字或者多重启几次程序。日常新搜到的职位不受这个上限影响。
- **LinkedIn Easy Apply 半自动投递会操作你真实登录的 LinkedIn 账号**，风险比上面"非官方抓取"更高一层——抓取是匿名只读请求，这个功能是在一个真实登录会话里做交互操作。缓解方式是：真实可见浏览器窗口（不是后台隐形操作）+ 会自动填写/回答已经在设置页配置过的字段和问题、自动点"下一步"翻页，但遇到没配置过的问题、或者已经翻到最后确认页时一定会停下来；代码里没有、也不会有点击最终"提交申请"的逻辑，这一步永远需要你本人在弹出的窗口里亲自确认，详见下方"LinkedIn Easy Apply 半自动投递怎么用"。

## 安装

```bash
cd newjob
python3 -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## 配置 API Key（自动分析功能必需）

自动分析功能需要调用 LLM API，二选一，通过环境变量传入，不写进 `config.json`：

**Claude（默认）** — 在 https://console.anthropic.com 申请 key：

```bash
export ANTHROPIC_API_KEY=sk-ant-xxxxx   # Windows: set ANTHROPIC_API_KEY=sk-ant-xxxxx
```

**DeepSeek（更便宜，价格约为 Claude 的十分之一到二十分之一）** — 在 https://platform.deepseek.com 申请 key，然后设置环境变量，并把 `config.json` 里的 `llm_provider` 字段改成 `"deepseek"`（目前这个开关还没做到设置页界面上，需要直接编辑 `config.json`）：

```bash
export DEEPSEEK_API_KEY=sk-xxxxx   # Windows: set DEEPSEEK_API_KEY=sk-xxxxx
```

不配置对应环境变量的话，定时搜索、待审核列表这些功能照常可用，只是点"自动分析"会报错提示未设置。

## 运行

```bash
python app.py
```

打开浏览器访问 `http://127.0.0.1:5050`。

首次打开后，在页面里：

1. 填写关键词（每行一个，如 `Senior Product Manager` / `AI产品经理`）。
2. 填写想搜索的城市（每行一个；留空一行表示不限地点/远程）。
3. 填写 `JD匹配追踪表.xlsx` 的完整本地路径（留空则默认 `~/Downloads/JD匹配追踪表.xlsx`）——既用于去重，也是自动分析结果的写入目标，和 `jd-resume-matcher` 技能共用同一份文件。
4. 填写基础简历 docx 的完整路径（留空则默认 `~/Downloads/Cathy_Yang_Resume_EN_AI.docx`），以及定制简历想保存到哪个目录（留空则跟基础简历同目录）。
5. 设置每天自动搜索的时间；旁边的"开启"勾选框可以关闭每天定时任务（关闭后不会自动跑，仍可随时手动点"立即搜索一次"）。
6. 点击"保存设置"。
7. 想立刻测试搜索效果，点"立即搜索一次"。

只要这个程序开着（`python app.py` 进程存活）且"开启"勾选框没关，就会按设置的时间每天自动跑一次，把新职位加进"待审核新职位"列表。

## 自动分析怎么用

每次搜索（定时触发，或点"立即搜索一次"）找到新职位后，会在后台自动依次分析所有还没分析成功过的"待审核"职位，不需要手动点击：

- 程序会把职位的 JD 正文（搜索时已经抓到）和你的基础简历一起发给配置的 LLM API，按 `jd-resume-matcher` 技能里定义的双因子模型（认知要求匹配度50% + 工作内容匹配度50%）计算总体匹配度。
- 结果会写入追踪表 xlsx 新的一行（在最上面），包含对比表全部字段。分析完成的职位点卡片（非标题、非按钮区域）即可弹窗看完整分析详情；卡片上的职位名称可以直接点击，新标签页跳转到原职位发布页，弹窗顶部也有同样的链接。未分析完成的职位卡片不可点击。
- 如果匹配度 ≥70% 且判定需要优化简历，会基于基础简历生成一份定制版 docx（改写措辞、突出相关经验，不编造未发生的经历），保存到设置的目录，并同时生成配套的 cover letter 写入追踪表。
- 分析完成后该职位在网页列表里会显示匹配度百分比；失败会显示"分析失败"，鼠标悬停能看到具体错误信息（比如 API key 没配、余额不足），程序下次搜索/启动时会自动重试。
- 也可以对某条职位点"AI 分析"手动立刻触发一次（不用等下次自动跑），比如想马上重试一个失败的。
- 页面最顶部（品牌栏右侧）有一个"AI分析"按钮，点击会对"待审核"里**所有**还没分析成功过的职位发起批量分析，不限于最近一次搜索新增的，也包括历史积压——想清理老早搜到、一直没轮到自动分析的旧记录时用这个。点下去按钮会变成红色的"停止分析"，再点一次会**立即**中止批次：页面马上恢复成"AI分析"、剩余排队的职位恢复成未分析状态，不再继续分析下一条；如果点停止的时候恰好有一条正在分析，这条职位调用LLM的网络请求技术上没法从外部强行掐断，会在后台默默跑完，但跑完的结果会被直接丢弃（不写库、不写追踪表），跟没分析过一样，之后需要的话可以再手动点它的"AI 分析"重新跑一次——也就是说这条被中断的职位那次LLM调用的费用已经产生但结果不会保留，属于中途叫停必然的代价。批次自然跑完（没有被中途停止）后按钮也会自动变回"AI分析"。注意积压条数多的话点一次可能触发几十上百次 LLM 调用，会产生相应的 API 费用，建议先看一眼"待审核"有多少条心里有数。
- JD正文没抓到的职位（来源站点没返回描述、被限流等），会直接跳过AI分析、不调用LLM——不会白花钱去分析一段空内容。这类职位的卡片上"AI 分析"按钮会换成"重新获取"，点击重新抓一次JD正文，抓到了会自动接着跑一次分析，页面会自动轮询、跑完自动刷新显示结果（不用自己再点"刷新"，一般几十秒到一两分钟，最长等4分钟，超时会提示"仍在后台处理中"，之后手动点刷新就能看到）；顶部工具栏的"全部重新获取JD"按钮可以批量处理"待审核"里所有JD缺失的职位（后台进行，处理条数多的话会比较慢，需要自己点"刷新"查看结果，不会自动刷新）。如果这条职位现在已经不在原来搜索关键词/城市的最新结果里了，重新获取可能会失败，可以再点一次重试。

批量自动分析在后台线程里跑，不会卡住"立即搜索一次"按钮或页面其他操作，而且是**逐条串行**分析的，不会同时并发跑多条（主要顾虑是同时写 `JD匹配追踪表.xlsx` 容易冲突、LLM API 也有速率限制）；每条大概几十秒到一两分钟（取决于 LLM 和 JD 正文长度），新增职位多的话整个批次可能要等几分钟才能都跑完。批次里正在跑的那一条，卡片按钮显示禁用态的"AI分析中…"；还没轮到的其它条显示"排队中…"；页面会每隔几秒自动轮询刷新，不需要手动点"刷新"就能看到匹配度陆续出现。批次跑得比较久的情况下（比如顶部"AI分析"按钮清理历史积压），如果排在后面还没轮到的职位在等待期间被手动标记"已忽略"，轮到它时会自动跳过、不再花钱分析。
- 已经生成定制简历/cover letter 的职位，卡片公司名那一行会出现"📄 定制简历"（点击在新标签页打开/下载 docx 文件）和"✉️ Cover Letter"（点击打开详情弹窗查看全文）链接。

AI 分析时还会顺带判断该公司是外企（总部在中国大陆以外，含在华子公司/办公室）还是中国大陆本土公司，职位卡片上会显示"🌍 外企"或"🇨🇳 中国公司"徽章；这个判断没有可靠的数据源，全靠 LLM 自身知识+JD 内容线索，不保证准确，判断不出的（比如没听说过的小公司）不显示徽章。职位列表页顶部工具栏有一组"🌍 外企 / 🇨🇳 国内公司 / 全部"筛选，**默认选中"外企"**——这个状态是页面级的，每次刷新页面都会重置回"外企"，不会记住上次的选择。"外企"筛选会隐藏已判定为"中国大陆本土公司"的职位，但*还没分析完成*或*AI 判断不出来*的职位仍会正常显示，不会被误藏；想看已排除的国内公司职位，切到"国内公司"筛选；想看全部不分类别，切到"全部"。

## 重点关注怎么用

每条职位卡片右侧操作区最左边有一个★星标按钮，点一下把这条职位标记为"重点关注"（星变成实心金色），再点一次取消。它跟审核状态（新/已收藏/已忽略）、投递状态都是独立的，标不标星不会改变职位的其它状态，还在"待审核"阶段就可以先标上；"已忽略"的卡片也保留这个按钮，方便随时取消标记。

工具栏"🌍 外企 / 🇨🇳 国内公司 / 全部"后面隔一条竖线，有一个"⭐ 重点关注"筛选按钮——它是独立开关，不是那组三选一的第四项，可以跟公司国籍、投递状态、以及顶部统计卡片的审核状态筛选任意叠加使用。点亮后只显示标了星的职位，再点一次取消。跟其它筛选一样，这个开关是页面级的，刷新页面会重置成关闭（星标本身存在数据库里，不会丢）。

## 投递状态跟踪怎么用

已收藏的职位卡片上有一个下拉框，可以手动标记这条职位当前的投递状态：待投 / 已投递 / 面试中 / 已拒绝 / Offer / 已婉拒，默认是"待投"。这个状态跟审核状态（新/已收藏/已忽略）是两回事，互不影响，纯手动维护，程序不会自动帮你改。"待审核"和"已忽略"的卡片不显示这个下拉框（还没决定要不要投的阶段用不上），把职位标记"已收藏"后就会出现。工具栏有对应的筛选 chip，可以按投递状态筛职位列表看。

## 面试准备怎么用

**自动生成**：把某条职位的投递状态改成「面试中」，程序会在后台自动生成一份针对这家公司/这个岗位的面试准备材料，通常要一两分钟。生成期间职位卡片上会显示"🎤 准备中…"，好了变成可点击的"🎤 面试准备"徽章，点它直接跳到材料页面。

同一条职位只会自动生成一次——反复切换投递状态不会重复调用 LLM 重复花钱。上次生成失败的（比如网络抖动）不算数，下次切到「面试中」会自动再试。

**在哪看**：点开职位卡片进详情弹窗，顶部有两个标签：「匹配分析」（原来的分析详情，内容没变）和「🎤 面试准备」。材料分四块：

- **公司 / 业务背景**：主营业务、这个岗位在组织里的位置、面试里可以主动聊的业务痛点、能显示你做过功课的切入点。
- **预测面试题**（10-15 道）：按"行为面 / 业务领域 / 技术方法论 / 职业动机"分组，点开每道题看"为什么会问这题"、答题要点（行为题按情境-任务-行动-结果组织）、以及简历里可以直接引用的那段经历或数字。
- **缺口应对话术**：对应「匹配分析」里标红的未达标要求，每条给出面试官大概率怎么问、建议怎么答（坦诚承认边界 + 可迁移经历 + 补齐计划，不会教你编造经历）、以及简历里能拿来顶的最接近的经历。这一块的输入直接来自匹配分析已经算好的结论，所以两个标签页看到的缺口是同一套，不会自相矛盾。
- **反问面试官 + 面试前准备清单**。

**重新生成**：面试准备标签页右上角有「🔄 重新生成」按钮，旁边可以填一个轮次标签（比如"二面"）。每生成一份都会保留，有两份以上时左上角会出现版本下拉，可以切回之前那份对照看；不想留的可以点「删除这份」。

**注意**：

- 这条职位必须有 JD 正文才能生成（没有的话先点卡片上的「重新获取」抓一次 JD）。
- 答题要点是基于你简历里真实存在的经历和数据生成的，prompt 里明确禁止编造经历、夸大数据——但 LLM 仍可能理解偏差，**用之前自己过一遍**，尤其是引用了具体数字的地方。
- 公司背景那一块是 LLM 基于自身知识写的，可能过时或不准，重要信息建议自己再核实一次。
- 生成失败不会影响投递状态本身（状态照常改成"面试中"），失败原因会显示在面试准备标签页里，点「重新生成」重试即可。

## 通用面试题库怎么用

上面那份是针对某一条职位的。而"自我介绍""为什么离开上一家""职业规划"这类问题每场面试都会遇到，跟具体公司无关——这些放在**顶栏的「面试题库」按钮**里，准备一次长期复用。

三个板块：

- **自我介绍**：60-90 秒口播稿，中英文各一版（外企面试开场常用英文）。
- **通用问题**：8-12 道高频题（离职原因、职业规划、优缺点、讲一次失败、期望薪资怎么谈等）。
- **STAR 故事库**：从简历里提炼的 3-5 个能反复复用的完整故事（从0到1、跨部门协作、冲突处理、数据驱动决策、失败复盘），按 情境-任务-行动-结果 完整写出来。面试时大部分行为题都能从这几个故事里取材。

**怎么用**：第一次点右上角「✨ AI 起草 / 补充」，程序会根据你的基础简历和设置里的搜索关键词（当成你在找的岗位方向）生成一份初稿，一两分钟。然后**逐条改成你自己的说法**——AI 初稿只是起点，改完点「保存」。

**改过的答案不会被覆盖**：每条右上角有徽章标着「AI 初稿」还是「已自定义」。再点「AI 起草 / 补充」时，只有还是「AI 初稿」的条目会被更新，你改过的一律跳过，手动加的题也自动受保护；已有的题一条都不会被删掉。所以想补充新问题的时候可以放心再点，不会丢东西。

也可以点每个板块下方的「+ 手动加一题」自己加题，或者删掉用不上的。

## LinkedIn Easy Apply 半自动投递怎么用

只支持 LinkedIn 的 Easy Apply（站内一键申请）职位，且这条职位必须已经生成过定制简历（`resume_path` 不为空）才会出现"Easy Apply"按钮；Indeed 或需要跳转到公司官网申请的 LinkedIn 职位不支持。

**首次使用前的准备**：

```bash
pip install -r requirements.txt   # 会装 Playwright
playwright install chrome         # 如果本机没有 Chrome，代码会退而用 Edge（channel="msedge"），不需要额外装
python -c "from easy_apply import ensure_logged_in; ensure_logged_in()"
```

最后一条命令会弹出一个真实可见的浏览器窗口停在 LinkedIn 登录页，手动登录一次即可（账号密码不会被程序读取或保存，只有登录后的 session cookie 会保存在本地 `.playwright_profile/linkedin/`，已加入 `.gitignore`，不会被提交到 git、也不要把这个目录发给别人）。登录态之后会一直复用，除非 LinkedIn 要求重新验证（这种情况下 Easy Apply 会报错提示"登录态可能已失效"，重新跑一次上面这条命令再登录即可）。

**建议先在"更多 → 设置"里填一份"Easy Apply 自动回答设置"**：工作签证/期望薪资/入职时间三个高频字段，加上"其它常见问题"文本框（每行一条，格式必须是 `问题关键词=答案`，注意是英文等号——不要用问题本身常带的冒号，格式不对的行保存时会有 toast 提示哪几行没识别出来）。这份资料决定了自动化能替你答多少题、走多远；不填也能用，只是每一步筛选问题都会停下来等你手动填。

**使用**：点击职位卡片上的"Easy Apply"按钮后，程序会：

1. 打开一个真实可见的浏览器窗口，导航到这条职位的 LinkedIn 页面。
2. 找到并点击"申请"/"快速申请"/"Easy Apply"按钮（LinkedIn 中文界面下这个按钮的文字不固定，代码同时匹配几种已知写法）。
3. 尽力自动填写：上传定制简历、粘贴 cover letter（找到匹配的输入框才会填）。
4. **自动回答设置页配置过的筛选问题，并自动点"下一步"翻页**——单选题按选项文字匹配你配置的答案，文本/下拉题按问题关键词匹配；LinkedIn 自动带出的资料（姓名/邮箱/电话等）已经有值的字段不会被覆盖。
5. **遇到没配置过答案的问题、或者已经翻到最后确认页（没有"下一步"按钮了）就停下**，浏览器窗口保持打开、不会自动关闭。**最终的检查和提交必须由你自己切换到那个窗口手动完成**——程序代码里没有、也不会有点击最终"提交申请"的逻辑，即使当场口头要求它继续点也不会照做，这是刻意的设计边界，详见 [spec/mission.md](spec/mission.md#投递自动化的边界2026-08-16-上线2026-08-16-修订)。
6. 同一时间只能有一个 Easy Apply 窗口在跑（Playwright 对同一份登录态 profile 是独占锁），处理完当前这条（提交或关闭窗口）之后才能开始下一条。

失败/停在半路的常见原因：登录态失效（重新登录）、这条职位其实不支持站内 Easy Apply（会跳到外部公司官网）、页面结构变化导致按钮/字段找不到（LinkedIn 会不定期调整前端，选择器可能需要跟着更新）、遇到没配置答案的问题、遇到用非标准写法（没有 `<legend>`）呈现的问题——这类问题即使配置了关键词也匹配不上，只能每次人工填。

## 跑回归测试

改完代码后在项目根目录跑：

```bash
.venv/Scripts/python.exe tests/run_all.py
```

三个套件全部用临时数据库 + 临时 config，LLM 调用全程 mock，**不会产生真实 API 费用，也不会碰你的 `jobs.db` 和 `config.json`**。最后还会用 `node --check` 检查两个 JS 文件的语法（没装 node 会报缺少可执行文件）。

全部通过时最后一行是 `ALL PASS (3 suites + 2 js files)`；有失败会列出是哪个套件，退出码非 0。

输出里会出现几段 `RuntimeError: 炸了` / `模拟LLM报错` 的 traceback，那是测试**故意**触发的异常分支（验证"生成失败不连累状态更新""失败后标志位要清掉"），不是真的报错。

单独跑某一个套件也可以：`.venv/Scripts/python.exe tests/test_bank.py`。

## 已知限制

- **"只看外企"判断不保证准确**：没有权威的公司国籍数据源，全靠 AI 根据公司名称和 JD 内容自行判断，可能出错（比如把外资在华子公司误判成本土公司，或反之），建议默认的"外企"筛选下偶尔切到"全部"确认没有漏看感兴趣的职位。
- **Easy Apply 的按钮/字段选择器可能因 LinkedIn 前端改版而失效**：目前的选择器是根据实测调整出来的（中文界面下 Easy Apply 按钮文字见过"申请""快速申请"两种写法），不是官方稳定接口，LinkedIn 改版后可能需要重新调整 `easy_apply.py`。

## 文件说明

- `app.py`：Flask 服务 + API。
- `scraper.py`：单次搜索逻辑（调用 python-jobspy，按关键词×城市循环，抓取JD正文，去重后入库）。
- `scheduler.py`：APScheduler 定时任务。
- `models.py`：SQLite 存储（`jobs.db`，运行后自动生成，已加入 .gitignore）。
- `tracker_xlsx.py`：只读追踪表工具，用于搜索阶段的去重判断。
- `tracker_utils.py`：追踪表写入工具（复用自 `jd-resume-matcher` 技能的 `scripts/tracker_utils.py`，保证格式/列结构完全一致）。
- `resume_docx.py`：读取基础简历文本、按段落索引生成定制版简历 docx。
- `llm.py`：统一的 LLM 调用层，屏蔽 Anthropic / DeepSeek 的接口差异（单轮/多轮对话、system prompt、max_tokens），`analyzer.py` 和 `interview.py` 共用。
- `analyzer.py`：JD-简历匹配分析的 prompt，解析双因子匹配度结果。
- `interview.py`：面试准备（单职位准备材料 + 通用题库）的 prompt 和 LLM 调用（不碰数据库，编排在 `pipeline.py`）。
- `pipeline.py`：把"取JD → 调用analyzer → 视匹配度生成简历/cover letter → 写入追踪表 → 更新任务状态"串起来的编排逻辑，以及面试准备的生成编排。
- `job_state.py`：进程内内存状态（AI分析排队/进行中、Easy Apply 启动中/失败、面试准备生成中），不持久化，重启后重新触发即可。
- `easy_apply.py`：LinkedIn Easy Apply 半自动投递的 Playwright 自动化逻辑，跟 `scraper.py`（纯 HTTP 抓取）分开。
- `config.py` / `config.json`：搜索与分析配置（`config.json` 首次运行自动生成，已加入 .gitignore，因为里面可能含本地文件路径）。
- `templates/`, `static/`：前端页面。
- `tests/`：回归测试。`run_all.py` 是统一入口（每个套件起独立子进程，避免 monkeypatch 互相污染）；`test_prep.py` 覆盖单职位面试准备，`test_bank.py` 覆盖通用题库（重点是"用户改过的答案不被重新起草覆盖"），`test_frontend.py` 对模板/JS/CSS 的接线做静态断言。
