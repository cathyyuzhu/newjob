## 一句话结论

**想法可行，但可行的不是你直觉里那一种。**

"开放给其他用户 + 收一次性费用"里，**一次性收费这个直觉是对的**（下面第三节会说为什么它比订阅更适合求职这个场景），**"开放"这个词的默认理解是错的**——如果理解成"我搭一个网站让大家注册来用"（托管 SaaS），三条独立的理由各自都足以否掉它（第二节）。

真正可行的形态是：

> **本地自托管 + 一次性买断激活码 + 用户自带 API Key（BYOK）**，卖给一个被刻意收窄的人群：**在中国找外企/英文远程岗、且能接受自己配 API Key 的技术型求职者**。

而**第一步不是写代码**。第一步是用 0 行代码验证有没有人愿意付钱，成本 3–5 小时，不影响你现在的求职（第四节阶段 0）。

## 二、先说不可行的：为什么托管版 SaaS 这条路不要走

不是"难"，是三条独立的理由，任意一条单独成立都足以否掉。

### 2.1 技术：单用户假设是长在骨头里的，不是一层皮

代码库里"只有一个用户"这个假设的分布情况（不是我猜的，是逐个文件核过的）：

| 位置 | 现状 | 多租户要改成什么 |
|---|---|---|
| `config.py` | 全局单例 `config.json`，一份关键词/城市/模型/简历路径 | 每用户一份配置，落库、加租户维度 |
| `models.py` / `jobs.db` | 单个 SQLite 文件，所有表都没有 `user_id` | 全表加租户列 + 迁移 + 隔离验证（约 20 张表规模） |
| `resume_store.py` / `resumes/` | 一份基础简历，路径写在全局配置里 | 对象存储 + 每用户命名空间 + 加密静态存储 |
| API Key | 进程环境变量 `ANTHROPIC_API_KEY` / `DEEPSEEK_API_KEY` | 每用户密钥托管（或强制 BYOK） |
| `app.py` | `host="127.0.0.1"`，**零鉴权**，Flask 开发服务器 | 上生产 WSGI + 注册登录 + 会话 + 权限 + CSRF |
| `scheduler.py` | APScheduler 跑在 Web 进程里 | 独立 worker + 任务队列（跟 tech-solution 里"不引入 Celery/Redis"的既有取舍直接冲突） |
| `tracker_xlsx.py` | 用户本机绝对路径的 xlsx，openpyxl 整份读写 | 并发写会互相覆盖，必须换成数据库或每用户独立文件 |
| `easy_apply.py` / `linkedin_tracker.py` / `linkedin_how_you_fit.py` | Playwright 持久化 profile `.playwright_profile/linkedin/`，**独占锁**，且承载真实 LinkedIn 登录态 | 见 2.2——这一条不是工程问题 |

粗估：不含 2.2 那部分，**多租户改造 4–6 周全职**，且改完之后每加一个功能都要多考虑一层隔离。对一个还在紧迫求职期的人来说，这个投入的机会成本是"这段时间本来能投的简历"。

### 2.2 合规与责任：登录态这条线不能跨

自用时，LinkedIn 非官方抓取的 ToS 风险是**你自己承担**（README「重要说明/边界」里已经写清并被你接受）。托管版有两处性质变化：

1. **抓取从你的 IP 变成服务器 IP**：所有用户共用出口，封禁从"我的号被限流"变成"全体用户同时不可用"，且责任主体从个人用户变成服务提供者。
2. **`.playwright_profile/` 里是用户真实的 LinkedIn 登录 cookie**。托管 = 你替陌生人保管他的求职主账号登录态。这是安全和法律上的红线，不能因为"技术上做得到"就做。**自托管形态天然规避这一条**：登录态永远只在用户自己电脑上。

### 2.3 成本：托管 + 一次性付费在数学上不成立

README 已经算过：DeepSeek 档位每天几毛到几块，Claude 档位贵一个数量级。按 DeepSeek 中位数估，一个活跃用户 **¥30–100/月** 的 API 成本。

- 收 ¥99 一次性 → **第 2 个月开始净亏**，且用户越活跃亏得越多（成本结构反向激励，最糟糕的一种）。
- 改成订阅解决亏损，但订阅撞上 product-review 第六节那条：**免费档已把心理价格锚到 0**（Simplify 免费、Jobright 有免费档、Teal 核心免费）。

**结论：如果要收一次性费用，就必须 BYOK（用户自己出 API 钱）。这不是妥协，是唯一自洽的组合。** 顺带说，BYOK + 一次性买断在 2026 年已经是独立开发者卖 AI 工具的成熟范式，不是你独创的怪招。

## 三、可行的三条路（按推荐排序）

### 路 A（推荐）：自托管 + 一次性买断 + BYOK

卖一个能在用户自己电脑上跑起来的完整程序，附带激活码，用户自己配 Claude/DeepSeek 的 key。

- **优点**：你的 API 成本恒等于 0；用户数据不出他自己的电脑（这是卖点，写进落地页）；抓取风险分散到各用户自己的 IP 和账号；跟"一次性付费"的诉求天然吻合；不需要服务器、不需要运维、不需要 7x24 待命。
- **缺点/真正的工作量**：**分发能力**，不是功能。今天的安装路径（建 venv、pip install、配环境变量、`python app.py`）会挡掉 90% 的求职者。路 A 的核心工程投入就是把这一段做成"下载、双击、跟着向导走"。
- **谁会买**：能看懂"自己去 platform.deepseek.com 申请一个 key"这句话的人。这个人群小，但**恰好是你自己**——你懂他们的痛点，也不需要为他们做客服式的手把手引导。

### 路 B：开源核心 + 付费增值

代码开源（GitHub 获客），收费卖：① 打包好的一键安装版；② 高级模块（偏好学习 / 面试题库）；③ 付费社群（知识星球 / 微信群，卖的是求职方法论+陪伴，不是软件）。

- product-review 第十节第 3 条已经提过这条，理由是"中国求职者找外企岗"这个人群没有对应开源项目，而你的中文踩坑文档（`tech-solution.md` 那种密度）本身有稀缺性。
- 跟路 A 不冲突，**可以同时做**：开源仓库当获客页，一键安装版收费。这是独立开发者最常见的组合。
- 风险：开源之前必须做完第六节的脱敏，尤其是 **git 历史里已经有你的真实数据**（见 6.1，这是硬阻塞项）。

### 路 C：不卖软件，卖服务（最快能收到钱的一条）

你用自己的工具，替别人跑完整条链路：匹配分析 + 定制简历 + 面试准备 + 一次 1v1 复盘。定价 ¥299–999/人。

- **今天就能开始，一行代码都不用写。** 也是路 A 最好的需求验证器——愿意为结果付 ¥399 的人，比"觉得这个工具挺酷"的人真实一万倍。
- 顺带解决 product-review 反复强调的问题：你会被迫看别人的简历和 JD，那是校准评分器最好的样本来源，而你自己一个人跑一辈子也攒不出这个量。
- 缺点：不可规模化，按小时卖时间。但在**验证阶段**这恰恰是优点。

### 明确不推荐

- **托管 SaaS 订阅**：理由见第二节，三条独立否决。
- **做成免费+广告/流量变现**：求职工具的用户生命周期 1–3 个月，攒不出广告需要的留存和 DAU。
- **卖"包投递"服务**：product-review 第六节的市场数据是反的——自动投递回复率 1–3%，方向是负和竞争，而且这跟你自己的产品红线（永不自动点提交）自相矛盾。

## 四、分阶段操作手册

判据贯穿始终：**每个阶段都有一个"达不到就停"的量化门槛，达不到就不进入下一阶段。** 这是防止你在求职紧迫期把两个月扔进一个没人要的产品里的唯一保护。

### 阶段 0 · 需求验证（本周，3–5 小时，0 行代码）

**目标：确认"陌生人愿意为这个东西掏钱"，而不是"陌生人觉得这个东西挺酷"。**

具体动作：

1. **写 3 篇内容**，全部用你自己的真实数据当素材（这是别人抄不走的部分）：
   - 选题一：《我用 AI 筛了 281 个职位，最后只投了 5 个》——讲降噪战果（281 → 粗筛剩 104 → 去重剩 5），结论落在"海投是负和游戏"。
   - 选题二：《AI 给我打 83 分的职位，我一个都没投——聊聊 AI 匹配度为什么不准》——讲 37 条越过 70% 线里你亲手忽略 11 条这个反直觉发现。这篇是**最有传播力的**，因为它反的是所有同类工具的宣传口径。
   - 选题三：《我给自己写了个求职工具，它记住了我讨厌什么样的工作》——讲偏好学习，这是 product-review 认定的唯一结构性差异点。
2. **每篇文末挂同一个链接**：一个问卷（腾讯问卷/Google Form），三个问题——你现在在找什么岗？最烦的是哪一步？如果有个本地跑、数据不外传、需要自己配 API key 的工具，¥129 你会买吗（会/看情况/不会）？
3. 同时在问卷里放一句：**"想让我用这套工具帮你跑一次完整分析（¥399）？留个联系方式。"** ——这是路 C 的入口，也是最硬的信号。

**门槛（7 天内）**：≥30 份问卷 且 ≥5 人选"会买" 或 ≥2 人真的预约了 ¥399 服务。

- 达标 → 进阶段 0.5。
- **不达标 → 停在这里。** 不是失败，是省下了 6 周。回去继续求职，这三篇内容本身对你的个人品牌和被 HR 看见有正外部性，不白写。

### 阶段 0.5 · 付费内测（2 周，3–5 人，2026-09-08 补入）

这一阶段是讨论"要不要先开内测"时补进来的，**它纠正了本文初稿的一个排序错误**：初稿把打包（阶段 1）排在接触真实用户之前，等于**闭着眼睛做安装器**——而"陌生人到底卡在哪一步"恰恰只能靠看别人装一次才知道。所以内测在阶段 1 之前，不在之后。

**两条硬规则：**

1. **收钱，不做免费内测。** 免费内测测不出唯一需要知道的那件事（有没有人愿意付钱），还会**把你本来就很窄的人群烧掉一遍**——拿过免费版的人后面不会再买。做法：向阶段 0 问卷里选了"会买"的人收早鸟价 ¥69，**无条件退款**（装不上、跑不通、不想要了，都退）。收了钱的内测同时就是付费验证，两件事一次做完。
2. **3–5 人，不是 20 人。** 这个阶段还没有安装包，每个人都要你陪 30 分钟装一次——**这正是目的**：你在旁边看，不替他操作，记下他卡在哪。N=5 是你能亲自陪完的上限，N=20 会在求职最紧的时候把你变成客服。

**内测范围要砍窄（降低你要支撑的面）：**

- **只开 Indeed，LinkedIn 抓取默认关，Easy Apply 完全不进内测。** 内测用户拿自己真实的 LinkedIn 账号撞限流/封号，消息会传回你正要经营的那个小圈子，代价远超收益。
- **绝不加埋点/遥测。** "数据不出你自己电脑"是这个产品的核心卖点，为了内测方便加个上报，等于把卖点亲手拆了。要数据就直接问用户、让他截图发你。

**开始之前先把这三个问题写死**（不写死就会退化成含糊的"求反馈"）：

1. **装得上吗**：从下载到第一次搜索出结果，花了多少分钟、卡在哪一步。
2. **他的简历跑得通吗**：解析出多少个段落（README 已经警告过文本框/图片版简历读不到）；匹配分析的结论他认不认；定制简历有没有保住他自己的排版。
3. **第二周他还在打开吗**——**这是最关键的一条**。付了 ¥69 却在第三天就不再打开，说明产品还不能卖，跟他嘴上说"挺好用的"无关。

**门槛（2 周结束时）**：5 个人里 ≥2 人在第二周仍在使用，且 ≥3 人的简历能完整跑通匹配分析。

- 达标 → 进阶段 1，且阶段 1 的清单按内测记录到的卡点重排。
- 不达标 → 退款，回去修被暴露出来的那几个根本问题，**不要进阶段 1**。

**顺带拿到的东西**：3–5 份别人的真实简历 + 他们的忽略/收藏行为。这是 [product-review.md](product-review.md) 反复说的"校准评分器唯一缺的样本"——你一个人跑一辈子也攒不出别人的数据。同时也别指望内测期评分器表现好：偏好档案需要攒够忽略记录才会生成，新用户是**冷启动**状态，这一点要提前跟内测用户讲明，别让他们拿冷启动的分数当产品结论。

**不要在内测期做的事**：边收反馈边改功能（会把 2 周拖成 2 个月）、延长内测窗口、为了留住人而免掉那 ¥69。

### 阶段 1 · 可分发化（2 周，内测达标后才做）

注意：这一阶段**不做多租户**，只做"让另一台电脑上的陌生人能跑起来"。**清单顺序按阶段 0.5 观察到的真实卡点重排**，下面是未经内测校正的初始猜测。

- [ ] **首启向导**：第一次打开时引导填 API Key（界面里填，不再要求设环境变量）、上传简历、填关键词城市。现在这些散落在设置页和环境变量里，对陌生人是断的。
- [ ] **打包**：PyInstaller 或 一键脚本（Win `.bat` / Mac `.sh`），目标是"下载解压双击"。Playwright 的浏览器下载要处理好（首次运行时装，带进度提示，不要静默卡住）。
- [ ] **剥离"你自己的东西"**：默认关键词从 `Senior Product Manager` / `AI产品经理` 改成空；追踪表默认路径、`documents/` 里你的个人面试笔记、`JD匹配追踪表.xlsx` 全部移出分发包。
- [ ] **LinkedIn 默认关闭**：`DEFAULT_CONFIG["sites"]` 去掉 `linkedin`，改成用户主动打开时弹一次风险告知（见 6.2）。
- [ ] **脱敏与 git 历史清理**（硬阻塞，见 6.1）。
- [ ] **加 LICENSE**（现在仓库里没有；商业分发必须明确）。
- [ ] **面向陌生人重写 README**：现在这份 80KB 的 README 是写给你自己的操作手册，信息密度对新用户是劝退级的。拆成"5 分钟上手" + "完整手册"两份。

### 阶段 2 · 收款与发货（1 周）

- **海外/技术人群**：Gumroad、Lemon Squeezy、Paddle、Dodo Payments 之类的 MoR（Merchant of Record）——它们代收代扣税、自动生成并邮件发激活码，个人开发者不用自己开公司。Dodo 在 2026 年的独立开发者圈子里被推荐较多（4% + $0.40/笔量级）。
- **国内**：
  - 最快：**爱发电**（6% 服务费，创作者可直接售卖虚拟商品，个人主体即可）。
  - 或 **知识星球**（把软件当社群福利，卖的是社群）。
  - 正规长期：**个体工商户营业执照 + 微信支付商户号**（约 0.6% 费率 + 微信认证 300 元/年，执照本身 0–200 元）。等有稳定流水了再办，别一开始就折腾。
- **激活码实现（重要，别做复杂了）**：做成**离线可验证的签名 license 文件**——你本地用私钥对 `{邮箱, 购买时间, 版本}` 签名生成一串码，程序内置公钥离线校验。**不要自建校验服务器**，那意味着你要保证一台服务器 7x24 活着，否则所有用户同时用不了软件，而这正是自托管形态本来要规避的东西。
- **退款政策**：无条件 7 天退款，写在购买页最显眼的地方。数字商品退款成本≈0，但它能显著降低陌生人下单门槛。

### 阶段 3 · 触达用户（持续，见第五节）

### 阶段 4 · 只有跑出 ≥50 个付费用户，才重新评估托管版

到那时你手上会有：真实的付费转化率、用户最常卡在哪一步、以及最重要的——**别人的求职数据**，那是评分器唯一的校准来源。在此之前谈多租户都是空谈。

## 五、怎么触达用户

### 5.1 先把人群收窄

不要说"给求职者用"。目标人群是：

> **在中国找外企 / 英文岗 / 远程岗，本身有一定技术背景（能自己申请 API key），且正在密集投递期的人。**

窄到这个程度有三个好处：① 内容选题自动明确；② 自托管 + BYOK 的门槛不再是缺点，而是天然的人群筛选器；③ **这就是你自己**——你不需要做用户调研就知道他们在想什么。

### 5.2 渠道清单（按性价比排序）

| 渠道 | 怎么用 | 为什么适合 |
|---|---|---|
| **小红书** | 图文过程记录："求职第 N 天，我的 AI 工具今天筛掉了 47 个岗" | 求职 + AI 工具双赛道流量都在，独立开发者的第一批用户常来自这里 |
| **即刻** | 发开发过程、发数据发现，混"独立开发"和"AI"圈 | 种子用户密度最高、对 BYOK 这种形态接受度最好的中文社区 |
| **V2EX（分享创造节点）** | 一篇正经的项目帖，重点写技术取舍不写吹嘘 | 技术型求职者密度高，且正好是能接受自托管的人 |
| **GitHub（走路 B 才有）** | 开源仓库本身就是落地页，中文踩坑文档是稀缺品 | 长尾流量，且"作者本人在用"的可信度最高 |
| **脉脉** | 外企求职话题下的经验帖 | 外企求职者密度最高的中文平台 |
| **公众号 / 小报童** | 把三篇内容沉淀成长文，做邮件/订阅沉淀 | 承接前面渠道的流量，避免全押在平台算法上 |
| **Product Hunt / Hacker News** | **只有做了英文版才有意义**，否则别浪费机会 | 一次性爆发流量，但转化人群跟你的窄人群未必重合 |

### 5.3 内容策略：卖的不是工具，是你的求职实录

这是整个 go-to-market 里唯一有护城河的部分。同类工具的宣传全是"AI 帮你匹配、一键投递、提升 10 倍效率"，同质化到没人信。而你有别人没有的东西：

- 一个正在真实求职、且已离职的人的**第一人称过程**；
- `jobs.db` 里的**真实数据**（281 条抓取 / 63% 被粗筛挡掉 / 37 条高分里只投 5 条）；
- 一份诚实到反常的产品评估——**你自己写的文档里承认"评分器已被证伪"**。

**把"AI 匹配度不准"这件事讲出来，比讲"我的 AI 匹配度很准"可信一百倍**，而且直接建立差异化。这条内容线索是免费的、独家的、且不会被抄。

### 5.4 明确不做

投流买量、SEO 站群、AI 批量生成的水文、在求职群里刷链接。人群太窄、客单价太低，付费获客的数学永远算不平；而且求职者社群对硬广的容忍度极低，一次刷屏就会被踢。

## 六、卖之前必须处理的风险清单

### 6.1 【硬阻塞】仓库里和 git 历史里有你的真实个人数据

核过的事实：

- **`JD匹配追踪表.xlsx`（636 KB）当前就在仓库里被 git 跟踪**，里面是你真实的职位分析记录。
- git 历史里还添加过 `Amazon_Interview_Prep.pdf`。
- `documents/` 下有你的个人面试准备笔记。

`.gitignore` 挡住的是 `jobs.db` / `config.json` / `resumes/`，**挡不住这几个已经被跟踪的文件**。开源或分发之前必须：① 从跟踪中移除并加进 `.gitignore`；② 用 `git filter-repo` 之类的工具清理历史（或者更省事：**新建一个干净的分发仓库，不带历史**）。这条不做完，路 B 一步都不能走。

### 6.2 LinkedIn ToS：自用和卖给别人是两件事

自用时风险你自己担；**卖给别人时你成了"提供抓取工具并从中获利"的一方**，性质变了。缓解措施（写进阶段 1）：

- 分发版默认**关闭** LinkedIn 抓取（`sites` 只留 `indeed`），用户主动开启时弹一次明确的风险告知，让他自己点同意。
- Easy Apply 那条"代码里没有、也不会有点击提交申请的逻辑"的红线**不要动**——它现在从"产品洁癖"升级成了**法律和市场上的双重卖点**（product-review 第六节：64% 招聘者已在反感雷同申请）。
- 安装时的免责声明：不承诺求职结果、不承诺账号安全、抓取风险用户自担。

### 6.3 依赖许可证

`python-jobspy` 是 **MIT**（已核实），可商业分发。其余依赖（flask / APScheduler / openpyxl / anthropic / python-docx / playwright / pymupdf）都是宽松许可证量级，但**正式发售前要完整过一遍并附上第三方许可证清单**，这是分发商业软件的标准动作。

### 6.4 宣传口径

不要出现"包就业""保证 offer""通过率提升 X%"这类表述——既无法证实，也踩国内求职服务类广告的合规线。口径统一到"帮你少看无关职位、少投不想去的岗"。
