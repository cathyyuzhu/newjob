## 一句话结论

**降噪这一层已经做成了，产品该往上走一层。**

上一份快照（08-16）说"效果闭环从未闭上"。两天后这句话已经过时了——库里有了 6 条已投递、24 条已生成材料，闭环的第一段数据出来了。而这批数据带来的结论比"还没验证"严重得多：

> **在 37 条越过 70% 投递线的职位里，你亲手忽略了 11 条，只投了 5 条。分数最高的那条被忽略的职位（0.835），比你实际投出去的 5 条里的每一条分数都高。**

评分器不是"还没被验证"，是**已经被验证了，而且没通过**。首页最醒目的那个数字「N 条越过 70% 投递线」，实际转化率是 13.5%。

同时，使用者提出的 7 条痛点里有 6 条指向同一件事：**这个产品是一个数据库加一排按钮，不是一条工作流**。它能告诉你"这 37 条分数够高"，但不能告诉你"今天该干什么、这条到底该不该投、你到底想要什么样的工作"。在已离职的紧迫期，这个缺口的代价是直接的——每天打开它，却不知道该做什么。

好消息是：**修这三件事的原材料，你已经攒齐了**（52 条忽略记录、13 条星标、6 条投递），只是从来没被用过。

## 二、使用者的 7 条痛点 → 收敛到 3 个根因

痛点是使用者本人在真实使用中提的，逐条列出并归因：

| # | 原话（摘要） | 根因 |
|---|---|---|
| ③ | 打分不信任，分高的职位综合并不吸引人；想反馈原因让打分自我迭代 | **A. 评分器没有记忆** |
| ⑦ | 想要总结我的职位偏好 + 综合建议 + 每日活动总结 | **A. 评分器没有记忆** |
| ④ | 每天上来不知道要做什么，想要可勾选的每日任务清单 | **B. 没有工作流状态机** |
| ⑥ | 投递后要手动标记已投 | **B. 没有工作流状态机** |
| ① | LinkedIn 推荐的职位这里抓不到，还得自己上 LinkedIn 看 | **C. 抓取层** |
| ② | LinkedIn 和 Indeed 有重复职位 | **C. 抓取层** |
| ⑤ | 投递要手动；不重点关注的职位能否自动投 | 边界问题，见第八节 |

### 根因 A：评分器没有记忆

`analyzer.py` 的 `PROMPT_TEMPLATE` 只看「这份简历 × 这条 JD」。它**从来不知道**你已经忽略了 52 条、星标了 13 条、投递了 6 条。每一条职位都是从零开始评的第一条职位。

这直接造成三件事：
1. 分数无法收敛到你的真实偏好（→ 痛点 ③）
2. 系统无法回答"我的偏好是什么"（→ 痛点 ⑦）
3. 分数分布挤在 0.60–0.845 这个窄带里，**决策区间只有 0.15 宽**，天然分不开

### 根因 B：没有工作流状态机

产品有完整的状态字段（`status` / `application_status` / `starred` / `tags`），但**没有任何东西把状态变成行动建议**。每天要做的事散落在四处：首页的「智能搜索」按钮、待审核卡片、职位详情页的「生成材料」、Easy Apply、投递后手动改下拉框。使用者要自己充当调度器。

数据上的佐证：`job_notes` 0 条、`resume_reviews` 0 次、85 条职位只有 1 条打了标签。**这三个功能都做完了、都能用、都没人用**——不是功能不好，是没有任何流程会把用户带到它们面前。

### 根因 C：抓取层

- 痛点 ①：LinkedIn 的「推荐职位」是登录态下的个性化流，jobspy 的匿名搜索接口结构上拿不到。硬啃需要维持登录会话 + 高频请求，正是最容易触发封号的操作——而 LinkedIn 是你求职的主通道。
- 痛点 ②：`make_dedupe_key()` 是「公司名 + 职位名」归一化后的**精确匹配**，`Senior Product Manager` 与 `Product Manager (Senior)`、`ABC Inc.` 与 `ABC` 全都算不同职位。最近一次运行 98/281 被判重复，说明**真实重复率还要更高**。

## 三、最大的机会：一份已经攒好、却完全没用的数据资产

52 条忽略 + 13 条星标 + 6 条投递 + 11 条"高分却被忽略"，是一套**高质量、强信号、完全属于你个人的偏好标注集**。它已经躺在库里两天了，产品的任何一个环节都没有读过它。

把它用起来的成本极低：

```
忽略时多问一句"为什么"（预设标签 + 一行自由文本）
  → 攒够阈值后一次 LLM 调用，总结成「偏好档案」
  → 注入 analyzer 的 prompt（以及未来的每日建议 / 求职策略）
```

一次 LLM 调用、一张新表、prompt 里加一段。**同时解决痛点 ③ 和 ⑦，并且是痛点 ⑦"综合建议"和未来求职策略模块唯一可能的地基。**

### 为什么这件事竞品做不了

联网调研的结论很明确：2026 年 AI 职位匹配的反馈学习（RLHF、行为信号、协同过滤）**全部发生在雇主端和平台端**——招聘方 accept/reject 候选人，平台学习招聘方偏好。to-C 求职工具这一侧几乎没人做，原因是结构性的：**平台方拿不到单个求职者的足量信号**（一个人一辈子也就投几百次，还分散在各个平台）。

而本项目是**本地单用户工具，所有信号天然全在你自己的库里**，且 LLM 时代不需要训练模型——总结成一段自然语言偏好档案注入 prompt 就够了。

这是整个项目里**唯一一个"因为是自用工具所以反而做得到"的能力**。上一份快照说本项目的差异化是"一条链、一套结论"，但也承认那一点用户难以感知。偏好学习不一样：**它是用户能直接感知的**（"它开始懂我了"），而且竞品结构上做不到。

如果要问"这个项目有没有可能成为产品"，这是目前唯一一个像样的答案。

## 四、仍然成立的核心竞争力

上一份快照列的三条，两天后重新检验，**全部仍然成立**，且有新证据：

1. **端到端链路上流动的是同一套结论**——`is_gap` 直接变成面试准备的缺口话术，不重新解析 JD。分立工具结构上做不到。
2. **成本工程被当产品设计做**——两层零成本粗筛实测挡掉 63%（177/281）；JD 为空不调用；按功能位分模型；材料生成从分析里拆出来（避免为没决定投的职位烧钱）。**分析报错 0 条、JD 缺失 0 条**，工程质量是真的。
3. **一条被反复捍卫的边界**——代码里永远没有点击「提交申请」的逻辑；筛选题只答配置过的，绝不让 LLM 现场猜。方向与主流竞品相反，而 2026 年的市场数据正在证明这个方向是对的（见第六节）。

新增一条：**回归测试是真的在防守真实故障**。8 个测试套件几乎每条断言都点名它锁住的那个 bug（措辞飘动导致题库重复、对话绝不写库、409 而不是笼统 500、批量生成跳过已生成的"不重复烧钱"）。这个质量意识在个人项目里罕见。

## 五、主要不足（按严重度，已按新数据重排）

### 1. ⚠️ 评分器已被验证不可用于决策——从"未验证"升级为"已证伪"

11/37 的高分职位被人工否决，1/41 的低分职位被人工捞回，星标比分数更能预测投递。**分数目前只能当"粗排"，不能当"决策线"**。而首页最大的那个数字（`clamp(2.6rem, 6.5vw, 4rem)` 的"N 条越过 70% 投递线"）恰恰在把它当决策线展示——**产品最醒目的位置，放着最不可信的数字**。

短期该做的不是重写打分模型，而是：① 收集否决原因，② 把"星标"这个已被证明有效的人工信号提升为一等公民，③ 首页主数字从"越过投递线"改成更诚实的口径。

### 2. ⚠️ 抓取层：边际收益已塌陷，且该抓的抓不到

新增率 1.8%，重复率 35%，而使用者真正想要的 LinkedIn 个性化推荐**结构上拿不到**。继续在抓取量上投入是负收益。上一份快照说"地基是纸糊的"仍然成立，但优先级要改：**不是去加固它，是别再往上盖楼了**。

### 3. 每天的使用路径是断的（根因 B）

`job_notes` 0、`resume_reviews` 0、tags 1/85 —— 三个完整功能零使用率。这不是功能问题，是**没有流程把用户带过去**。在紧迫求职期，这一条的实际代价最大。

### 4. 材料生成 80% 打水漂

24 条生成、20 条没投、7 条所在职位后来被忽略。这是全链路最贵的调用。当前触发点（职位详情页手动点）太靠前——在"决定要投"之前。

### 5. 面试准备的问题是形态，不是功能缺失

使用者在 [`解决问题方面的思考`](解决问题方面的思考) 里写得很直白：

> "AI 生成的答案不够满意，需要花较大力气"
> "准备面试问题的过程似乎不能给我带来成就感，因为它没有创造出新的东西，只是把我知道的东西表达出来"
> "我觉得它虚假，需要包装自己，也许我可以用更真诚真实的方式表达"

数据佐证：题库 16 条里 `work_history` 分类 **0 条**，`self_intro` 只有 1 条——最需要个人真实素材的两类，恰恰是空的。

**当前模块在做"替你写标准答案"，而这正好撞在使用者的抵触点上。** 这不是再加一个 P3 模拟面试能解决的，是形态要换：**少替你写，多向你提问，把你的真实经历问出来**。（顺带说，笔记里"跟 Claude 聊、用记忆功能"这个自救方案，本质上就是在要一个提问式的助手。）

### 6. 仍在的产品债

单份简历 / 单进程 / xlsx 无并发保护 / Flask 开发服务器无鉴权（"给第二个人用"要重写数据层和任务层）；粗筛靠中英文关键词硬编码，换职能方向整套重写；2000+ 行原生 JS 拼 DOM 且无真浏览器测试；`/jobs/<id>` 的 `.detail-layout` 没有移动端断点（`style.css:908`）；**未分析的职位点不进详情页**（`app.js:691` 的 `clickable` 判定）——而 `job_detail.js:98` 专门为这个状态写了空态，只能靠手敲 URL 才看得到。

## 六、竞品格局（2026-08-18 复查）

### 市场信号：海投的边际收益已经是负的

| 数据 | 来源 |
|---|---|
| LinkedIn 每分钟收到 **11,000 份**申请，同比 +45% | Clever CV / Metaintro |
| 单个岗位平均 **300+** 候选人，约为 2021 年的 3 倍 | Metaintro |
| **64%** 招聘者反映 AI 简历普及后"雷同申请"明显增多 | Metaintro |
| 自动投递工具回复率 **1–3%**；直接联系 hiring manager 回复率 **40–60%** | The Interview Guys / Zipply |
| 面试推进率约**腰斩**，"能被看见的人比以往更快拿到 offer，但几乎没人被看见" | Metaintro |
| **49%** 求职者因为过不了自动筛选而投更多岗——正是恶化的成因 | Metaintro |

**这套数据直接决定了本项目的战略方向：不要往投递自动化那半边走。** 那半边现在是负和竞争。

### 分段竞品

| 环节 | 竞品与定价 | 本项目相对位置 |
|---|---|---|
| 自动填表 / 投递 | **Simplify** 免费无限 autofill（Simplify+ $39.99/月）；**LazyApply** $99–999/年；**JobCopilot / Jobwizard / Massive** | 追不上，也不该追 |
| AI 匹配 + 推荐 | **Jobright**（免费档 + Turbo $17.99/周，含 match score / 定制简历 / Orion copilot） | 分段能力相当，但它的匹配同样不学个人偏好 |
| 追踪 CRM + 简历定制 | **Teal**（免费档 + 约 $29/月）、**Huntr**、**Jobscan**（约 $49.95/月）、Careerflow | 见下 |
| 面试准备 | Final Round AI；国内 牛客 / 面多多 / 白瓜 / 面试猫 / OfferGoose | 定位错开（外企 × 英文 × 个人题库） |

### 三个必须正视的结论

1. **Teal 的核心差异化就是 checklist-driven workflow**——2026 年的评测把它总结为"适合以清单驱动工作流为优先的求职者"。这印证痛点 ④ 是真需求，**而且是可被用户直接感知的差异点**（不像"一条链一套结论"那样难以察觉）。反过来说，这一块本项目目前是空白，而竞品拿它当卖点。
2. **免费档已经把心理价格锚到 0**——Simplify 免费、Jobright 有免费档、Huntr/Teal 有免费档。to-C 订阅这条路更难了。
3. **AIHawk（30k+ stars）2026-05-17 归档转只读、作者转做招聘方 to-B 产品**——这个信号继续成立。

### 唯一的空位

调研没有找到任何一个 to-C 求职工具在做**"从用户自己的忽略/收藏/投递行为反向学习个人偏好"**。原因见第三节——平台方结构上拿不到足量单用户信号。**这是目前唯一一个本项目有结构性优势的位置。**

## 七、大产品策略：从「降噪」升级到「决策」

当前叙事是 Signal —— "求职路上，滤掉噪音，只留信号"。**降噪已经做到了**：281 → 粗筛剩 104 → 去重剩 5，这是真实战果。

但降噪的终点是"给你 37 条高分职位"，而使用者的真实状态是：面对这 37 条，忽略了 11 条、投了 5 条、剩下 21 条悬着，并且不知道明天该干什么。

**降噪解决的是"看什么"，没解决"做什么"。** 下一层价值是三个问题：

| 问题 | 对应能力 | 对应痛点 |
|---|---|---|
| **今天该做什么？** | 每日任务清单 + 活动日报 | ④⑦ |
| **这条到底该不该投？** | 偏好档案驱动的评分 + 否决原因反馈 | ③ |
| **我到底想要什么样的工作？** | 求职策略 / 职位定位模块 | ⑦ + `解决问题方面的思考` |

第三个问题最深，也最不该被跳过——使用者的笔记已经诊断出"很多工作并不是自己想做的，因此热情不足"，而这正是"不愿准备面试"的上游原因。**这是一条完整的因果链：定位不清 → 投了不想去的岗 → 面试没热情 → 不愿准备。** 只修下游（再加一个模拟面试功能）不会有效果。

## 八、下一步优先级（按"已离职、很紧迫"重排）

评判标准只有一条：**这件事能不能在两周内增加真实的面试机会。**

### P0 · 本周

**P0-1 每日任务清单**（痛点 ④）
首页顶部一条按当前库状态自动生成的可勾选清单：今日抓取 / N 条待审核 / M 条待生成材料 / K 条待投递 / J 条投了超过 7 天该跟进。支持自定义条目。
> 成本最低、感知最强的一条。它把散落各处的按钮变成一条流程，顺带把零使用率的备注/体检/标签带到用户面前。竞品验证过（Teal）。

**P0-2 投递状态自动化**（痛点 ⑥）
Easy Apply 流程走完后自动置 `applied` 并记录投递时间；列表页加一键「我投了」；投递时间用于 P0-1 的跟进提醒。
> 这是效果闭环的入口。现在 6 条投递全靠手动改下拉框，会漏记；漏记则后面所有校准都无从谈起。

**P0-3 忽略原因收集 → 偏好档案**（痛点 ③⑦ 的地基）
忽略时弹一行原因（预设标签：薪资不符 / 职能不对 / 公司不感兴趣 / 地点 / 行业 / 层级不匹配 + 自由文本），存库。累计到阈值后一次 LLM 调用总结成「偏好档案」，注入 `analyzer.py` 的 prompt。
> 唯一能让痛点 ③ 真正成立的路径，也是唯一有结构性差异化的能力。11 条"高分被忽略"就是最好的冷启动样本——可以先补录这 11 条的原因。

### P1 · 两周内

**P1-4 每日/每周复盘报告**（痛点 ⑦）
今天审核了 N 条、投递了 M 条、生成材料 K 份；本周偏好总结；下一步综合建议。数据源就是 P0-2 和 P0-3。

**P1-5 LinkedIn 推荐职位手动导入**（痛点 ①）
**不硬啃个性化推荐流的抓取**（需登录态高频请求，封号风险直接命中求职主通道）。改做「粘贴 URL / 批量粘贴」导入通道：你在 LinkedIn 上看到好职位，复制链接贴进来，走完整的分析链路。
> 5% 的工作量拿 80% 的价值，且零封号风险。

**P1-6 跨源去重加固**（痛点 ②）
`make_dedupe_key()` 增加归一化：剥离 `Senior/Sr./资深`、括号后缀 `(Shanghai)`、公司后缀 `Inc./Ltd./有限公司`、全半角统一。可选加一层"同公司下职位名相似度"的兜底判断。

**P1-7 材料生成触发点后移**
从"职位详情页随时可点"改为"标记为准备投递时才生成"，或至少在忽略职位时提示已生成的材料。止住 80% 的浪费。

### P2 · 求职告一段落后

- 求职策略 / 职位定位模块完整版（与偏好档案联动，接住 `解决问题方面的思考` 那条因果链）
- 面试准备形态转向：提问式而非生成式
- UI/UX P1/P2 批次、模拟面试 P3、界面双语切换

### 明确建议冻结

roadmap 里的 **UI/UX P1 + P2 共约 57 条**、**P3 模拟面试**、**界面双语切换**——现在做这些不产生面试机会。

仅两个例外（因为它们挡住日常使用路径，各是几行的事）：
- `/jobs/<id>` 补移动端断点（`style.css:908` 的 `.detail-layout` 没有被 720px 块覆盖）
- 未分析职位允许点进详情页（`app.js:691`），空态已经写好了（`job_detail.js:98`）

### 一个顺手的修正

首页主数字建议从「N 条越过 70% 投递线」改成诚实的口径——例如「N 条待你决定」或「重点关注 N 条 · 待审核 M 条」。**在评分器被证伪的当下，把它的输出放在全页最大字号上，是在放大一个已知不可信的信号。**

## 九、待决策项：自动投递红线（痛点 ⑤）

使用者提出"对不那么重点关注的职位，能否自动操作浏览器完成投递"。这直接冲突 [mission.md](mission.md) 里的承诺："代码里没有、也不会有点击『提交申请』的逻辑……即使当场口头要求它继续点也不会照做。"

本节只算代价，不替使用者拍板。

| | **路 A：保持红线** | **路 B：分级自动提交** |
|---|---|---|
| 工作量 | 小——只需补齐 `easy_apply_profile` 的筛选题覆盖率，让自动化多走几步 | 大——需要提交后验证、失败重试、误投处理，而**误投不可撤销** |
| 风险 | 近乎 0 | **高**——LinkedIn 是你求职的主通道，封号 = 断掉主通道；且投出去的东西收不回来 |
| 预期收益 | 每条投递仍需约 2 分钟人工 | 长尾覆盖面提升，但**回复率 1–3%** |
| 与已有承诺 | 一致 | 需要正式修订 mission.md，并接受 README 里对使用者的那句承诺作废 |
| 与市场方向 | 顺——雇主端正在反感海投 | 逆——64% 招聘者已在识别雷同申请 |

### 第三条路（建议一并评估）

**不做自动提交，改做"自动判断哪些不值得投"。** 把投递从"多而广"压成"少而准"，用省下的时间做定向 outreach——这是唯一有数据支撑收益的方向（直接联系 hiring manager 回复率 40–60%，是自动投递的 20 倍）。

这条路和使用者自己的诊断是同向的：

> "如果投递太多，很多工作并不是自己想做的，我需要找到自己真正想做的职位。所以应该重新思考投递策略"

**痛点 ⑤ 的字面需求是"自动投更多"，但使用者自己的笔记诊断出的问题是"投了太多不想去的"。这两者方向相反。** 建议优先满足后者。

如果最终仍要走路 B，建议的最小形态是：仅对**明确手动标记为"低优先级"**的职位开启，且保留一份提交前快照供事后复盘——但仍需承认封号风险不可对冲。

## 十、商业化判断（更新）

上一份快照的结论（不看好直接卖给求职者的订阅产品）**基本维持**，理由不变：需求一次性、生命周期 1–3 个月、核心通道不合规、免费档已把价格锚到 0。2026-08-18 的复查只让这个判断更强（Simplify 免费、Jobright 有免费档）。

但有一处要**修正**：

上一份快照说"如果要选一个方向继续投入，该留下的是「匹配分析 + 定制简历 + 面试准备」这条无抓取依赖的主干"。这个判断的方向是对的（远离抓取层），但**选错了具体资产**——匹配分析和定制简历这两段，Jobscan / Teal / Jobright 都做，本项目在这一段没有护城河，而且第一节的数据说明本项目的评分器目前还不如竞品可靠。

**真正稀缺的是「个人偏好学习」**：从你自己的忽略/收藏/投递行为里学出"你到底想要什么样的工作"，再反过来驱动打分、每日建议和求职策略。调研范围内没有 to-C 竞品在做，且平台方结构上做不到。

修正后的三条路（按推荐排序）：

1. **偏好学习 + 求职决策助手**——把"降噪工具"做成"决策工具"。这是唯一有结构性差异化的方向，且**恰好就是 P0-3 到 P2 那条主线**，不需要额外投入。
2. **面试准备单独产品化**——不依赖抓取、付费意愿明确、成果可留存（题库是长期资产，`user_edited` 保护那套设计正好支撑"这是我的资产"的心智）。但**前提是先解决第五节第 5 条的形态问题**：现在这个形态连作者本人都不愿意用，这个信号必须当真。
3. **开源 + 自托管收影响力**——完成度加上 tech-solution.md 那种质量的中文踩坑文档，在 GitHub 上有稀缺性；"中国求职者找外企岗"这个人群没有对应开源项目。

### 但最重要的建议仍然是那句

**在讨论任何商业化之前，先把你自己的求职跑完。** 上一份快照写这句话时是 0 条投递；现在是 6 条。距离"投了 N 个 → 约面 M 个 → 拿到 offer"这个完整样本，还差最后一段——而你正处在最紧迫、也最容易拿到这个样本的时期。

这个样本是上面三条路里任意一条的入场券，也是唯一能真正校准评分器的东西。**在此期间，工具本身只做 P0 那三件、以及能直接省时间的 P1，其余全部冻结。**
